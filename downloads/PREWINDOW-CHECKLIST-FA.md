# چک‌لیست صبح فردا — «آیا چاپ ساعت ۱۱ سالم است؟»

> پنجرهٔ فعالیت: **۱۱:۰۰ تا ۱۴:۰۰** (با حاشیهٔ فعلی ۱۰:۳۰–۱۴:۱۵). بیرون از آن، Worker **هیچ کاری نمی‌کند**.
> پس باید **قبل از ۱۱** مطمئن شوید. این چک‌لیست حدود ۱۰ دقیقه وقت می‌برد.

---

## گام ۰ — قبل از هر چیز: نصب به‌روزرسانی

اگر بستهٔ ۱.۶۳ را هنوز نصب نکرده‌اید، **اول نصبش کنید** (ابزار تست پیش از پنجره داخل آن است):

1. بکاپ بگیرید (دیتابیس + `storage/` + `config.php`).
2. بستهٔ `ticket-update-1_62_96-to-1_63-...-r15.zip` را با مسیر رسمی `system-update.php` نصب کنید.
3. مطمئن شوید `VERSION` روی `1.63` است.

> اگر ۱.۶۲.۹۶ را نصب نکرده‌اید، اول بستهٔ `ticket-update-1.62.95-to-1.62.96-...zip` را نصب کنید (پیش‌نیاز است).

---

## گام ۱ — تست ۶۰ ثانیه‌ای (مهم‌ترین گام)

یک پنجرهٔ CMD باز کنید و این دو خط را اجرا کنید:

```bat
cd /d C:\xampp\htdocs\<پوشهٔ سامانه>
chcp 65001
C:\xampp\php\php.exe tools\prewindow_check.php
```

### نتیجه را این‌طور بخوانید

| خروجی | معنا | کار شما |
|---|---|---|
| `✅ آمادهٔ فردا` | هیچ ایرادی نیست | برو گام ۲ (تأیید نهایی) |
| `⚠️ کار می‌کند ولی N هشدار` | چاپ کار می‌کند اما نکته‌ای هست | هشدارها را بخوانید؛ اگر «heartbeat» یا «پرینتر» بود، گام ۳ |
| `❌ N ایراد مسدودکننده` | **چاپ ساعت ۱۱ کار نمی‌کند** | پایین هر FAIL توضیح داده؛ سریع رفع کنید |

### شش چیزی که ابزار می‌سنجد

1. **پنجره** — آیا ساعت ۱۱:۰۰ باز می‌شود؟ آیا **فردا** باز است؟ (اگر فردا تعطیل باشد، می‌گوید)
2. **پردازشگر** — آیا `enabled=1` است؟
3. **Worker** — آیا زنده است؟ (اگر آخرین اثرش بیش از ۱۵ دقیقه پیش باشد، FAIL می‌دهد)
4. **صف چاپ** — آیا ردیفی «واجد شرایط ولی چاپ‌نشده» مانده؟ آیا ردیفی در `printing` گیر کرده؟
5. **پرینتر** — فقط اتصال TCP تست می‌شود (**هیچ بایتی ارسال نمی‌شود**، کاغذ هدر نمی‌رود)
6. **رندر فیش** — آیا متن فیش اصلاً ساخته می‌شود؟

### اگر می‌خواهید بدانید ساعت ۱۱ چه می‌شود

```bat
C:\xampp\php\php.exe tools\prewindow_check.php --at "11:00"
```

یا برای روز دیگر:

```bat
C:\xampp\php\php.exe tools\prewindow_check.php --at "2026-11-16 11:00"
```

## گام ۲ — اگر همه سبز بود: تأیید نهایی با یک چاپ واقعی

تست بالا ثابت می‌کند «مسیر» سالم است. اگر می‌خواهید **کاغذ واقعی** هم ببینید:

```bat
C:\xampp\php\php.exe tools\print_test.php --send
```

⚠️ این **واقعاً چاپ می‌کند** (یک فیش نمونه). عمداً از تست پیش از پنجره جدا است تا تست اصلی هیچ کاغذی هدر ندهد.

اگر می‌خواهید بدون چاپ، فقط تصویر فیش را ببینید:

```bat
C:\xampp\php\php.exe tools\print_test.php --png
```
پیش‌نمایش: `storage\food_ticket_prints\netprint_preview.png`

## گام ۳ — اگر FAIL داشتید: رفع سریع

| FAIL | علت | رفع |
|---|---|---|
| «پنجرهٔ کاری غیرفعال است» | `window_enabled=0` | پنل ← فیش غذا ← تنظیمات ← پنجرهٔ فعالیت را فعال کنید |
| «ساعت ۱۱ باز نمی‌شود» | ساعت/روز اشتباه | همان‌جا `window_start` را `11:00` و روزها را چک کنید |
| «فردا بسته است» | فردا تعطیل است | طبیعی است؛ روز کاری بعد را با `--at` تست کنید |
| «پردازشگر غیرفعال است» | `enabled=0` | پنل ← فیش غذا ← فعال کردن پردازشگر |
| «Worker زنده نیست» | Task Scheduler | `taskschd.msc` ← تسک Worker غذا ← Run؛ اگر اجرا نشد، خطای آخرین اجرا را ببینید |
| «ردیف واجد شرایط مانده» | Worker چاپ نمی‌کند | گام ۳۱: پرینتر را چک کنید؛ سپس `diagnose_food_full.php` |
| «printing گیرکرده» | صف قفل شده | `php tools\diagnose_food_full.php` بخوانید؛ ردیف را با پنل آزاد کنید |
| «قفل کهنه مانده» | فایل lock قدیمی | Worker را یک‌بار ری‌استارت کنید (تسک را Run کنید) |
| «به پرینتر وصل نشد» | پرینتر خاموش/آدرس غلط | پرینتر روشن باشد، آدرس و پورت (پیش‌فرض ۹۱۰۰) درست باشد |
| «متن فیش ساخته نشد» | رندر خراب | `diagnose_food_full.php` را بفرستید |

## گام ۴ — اگر چیزی درست نشد: اطلاعات را برای من بفرستید

این دو فایل را بگیرید و بفرستید:

```bat
C:\xampp\php\php.exe tools\prewindow_check.php > prewindow-check.txt 2>&1
C:\xampp\php\php.exe tools\diagnose_food_full.php > diag-food-full.txt 2>&1
```

`diagnose_food_full.php` یک اسکن کامل ۰ تا ۱۰۰ است (فقط‌خواندنی، بدون چاپ). با آن می‌توانم دقیقاً بگویم کجای زنجیره شکسته.

---

## چرا این روش درست است؟

بدون این ابزار، تنها راه فهمیدن «چاپ کار می‌کند یا نه» صبر تا ساعت ۱۱ بود. و اگر ساعت ۱۱:۰۵ می‌فهمیدید خراب است، طبق تجربهٔ امروز وقتی برای تعمیر نمی‌ماند.

این ابزار **همان تابعی را صدا می‌زند که خود Worker صدا می‌زند** (`food_ticket_window_state`)، پس اگر می‌گوید «ساعت ۱۱ باز است»، Worker هم همان را می‌بیند. هیچ شبیه‌سازی موازی‌ای نیست.

---

## یک محدودیت صادقانه

هیچ ابزاری نمی‌تواند تضمین کند که **ساعت ۱۱ تردد جدیدی در فایل Access ثبت شود**. ابزار ثابت می‌کند: مسیر کد، پنجره، Worker، صف، پرینتر و رندر همه سالم‌اند. تنها متغیری که خارج از کنترل نرم‌افزار است، **خودِ دستگاه تردد** است (اگر ساعت ۱۱ کسی تردد نکند، فیشی هم نیست — که طبیعی است).

بهترین تأیید نهایی: ساعت ۱۱:۰۵ یک تردد آزمایشی بزنید و ببینید فیشش چاپ می‌شود.
