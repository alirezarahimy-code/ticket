## ۱) بستهٔ میانی — ۱.۶۳ ← ۱.۶۳.۱

```
نام فایل : ticket-update-1.63-to-1.63.1-r19-asset-identity-reset-20261116.zip
حجم     : 948,707 بایت (~۸۹۰ کیلوبایت)
SHA-256 : 2ec85fbbc479298e2096651f3411273e6dee7ec79c2d07ec59b177b6c69a805a
```

**۸۳ فایل، بدون مهاجرت، بدون تغییر جدول. — نسخهٔ r19**

**r19 — ریشهٔ «۱۲۵ در برابر ۸۹» پیدا و بسته شد:**

۱) **کلید هویت، آدرس IP را می‌بلعید.** تابع هویت، `CLIENT-192.168.1.50` را اول
   پیشوند‌زدایی می‌کرد و بعد نقطه را جداکنندهٔ نام دامنه می‌دید؛ نتیجه: هر سه
   آدرس `192.168.1.10` و `.11` و `.200` به هویت `192` می‌رسیدند. حالا IP پیش از
   هر نرمال‌سازی‌ای شناسایی و دست‌نخورده برگردانده می‌شود.

۲) **چهار مسیر درج، `hostname_key` را ست نمی‌کردند.** در MySQL مقدار `NULL` در
   یک ستون UNIQUE یکتا شمرده نمی‌شود، پس هر درج تازه یک رکورد جدید می‌ساخت —
   حتی برای همان کامپیوتر. هر سه مسیر فعال اصلاح شدند.

۳) **جست‌وجو با `OR` رکورد بیربط را می‌گرفت.** شرط
   `(asset_tag = ? OR hostname = ? OR serial_number = ?)` با تطابق روی هر یک از
   این سه، رکورد را برمی‌گرداند؛ اگر `asset_tag` با رکورد دیگری جور می‌شد،
   شناسنامهٔ سیستم اشتباه به‌روز می‌شد و سیستم واقعی رکورد تازه می‌ساخت. حالا
   اولویت صریح پله‌ای است: سریال ← MAC ← نام ← تگ.

۴) **هویت دیگر به IP وابسته نیست.** تابع تازهٔ `asset_stable_identity()` هویت
   دستگاه را از سریال سخت‌افزار، بعد MAC، و در آخر نام می‌سازد. اگر IP عوض شود،
   همان شناسنامه به‌روز می‌شود؛ رکورد دوم ساخته نمی‌شود.

**ابزار ادغام تکراری‌ها (برای پاک‌کردن ۳۶ رکورد اضافهٔ موجود):**

```
C:\xampp\php\php.exe tools\asset_dedupe.php
C:\xampp\php\php.exe tools\asset_dedupe.php --apply
C:\xampp\php\php.exe tools\asset_dedupe.php --apply --enforce
```

دستور اول فقط گزارش می‌دهد. حالا بر اساس **سریال سخت‌افزار** هم گروه‌بندی
می‌کند، نه فقط نام — پس رکوردهایی که با نام‌های مختلف برای یک دستگاه ساخته
شده‌اند هم پیدا می‌شوند. رکورد با کمترین id می‌ماند، فیلدهای خالی از بقیه پر
می‌شود، وابستگی‌ها منتقل می‌شوند، و بکاپ در جدول `asset_dedupe_backup_*` می‌ماند.

**دکمهٔ ریست (درخواست کاربر):** در «تنظیمات» کارت تازهٔ **ریست شناسنامه‌ها**
اضافه شد — فقط برای مدیر اصلی، با تایپ کلمهٔ «ریست» برای تأیید. پیش از حذف،
یک بکاپ کامل JSON در `storage/asset-reset/` ساخته می‌شود؛ اگر بکاپ نوشته نشود
هیچ رکوردی حذف نمی‌شود. همین کار از خط فرمان هم ممکن است:

```
C:\xampp\php\php.exe tools\asset_reset.php
C:\xampp\php\php.exe tools\asset_reset.php --apply
```

و بازگردانی بکاپ:

```
C:\xampp\php\php.exe tools\asset_reset_restore.php
C:\xampp\php\php.exe tools\asset_reset_restore.php <نام-فایل> --apply

## فیش‌های غذا برای روزهای گذشته

شام هر روز و ناهار پنجشنبه/جمعه/تعطیل رسمی خودکار ثبت می‌شوند — اما فقط **یک بار**،
در گذر پایان‌روز ساعت ۲۳ همان روز. هر شبی که Worker خاموش بوده، آن روز برای همیشه
خالی می‌ماند.

**دیگر لازم نیست دستی فیش بزنید.** در «تنظیمات سیستم ← اتصال پایگاه‌ها»، پایین صفحه،
کارت **«ثبت خودکار فیش روزهای گذشته»**: بازه را بدهید، «پیش‌نمایش» بزنید، بعد
«ثبت خودکار».

```bash
# یا از خط فرمان
php tools/backfill_food_auto_receipts.php --days 30             # فقط گزارش
php tools/backfill_food_auto_receipts.php --days 30 --apply     # ثبت واقعی
php tools/backfill_food_auto_receipts.php --from 2026-08-01 --to 2026-10-30 --apply
```

| قاعده | رفتار |
|-------|-------|
| ناهار فقط تعطیل | در روز کاری رد می‌شود |
| غیبت | کاربر غایب رد می‌شود |
| فیش واقعی چاپ‌شده | دست نمی‌خورد |
| اجرای دوباره | صفر ردیف تازه — بدون تکرار |
| چاپ فیزیکی | **هیچ** — فقط ثبت در سامانه |
| امروز | رد می‌شود؛ گذر شبانه پوشش می‌دهد |

بدون مهاجرت، بدون تغییر جدول، بدون مجوز تازه.

## فیش‌هایی که در صف چاپ ماندند (پرینتر خراب بود)

اگر پرینتر خراب باشد، کارکنانی که تردد می‌زنند در صف چاپ می‌مانند — نه چاپ
می‌شوند، نه تحویل ثبت می‌شود. پیش از این، سامانه آن‌ها را «دارای فیش» می‌دانست و
راهی برای اصلاح نبود.

**اکنون:** در **ثبت تردد**، دکمهٔ **«ثبت گروهی N فیشِ چاپ‌نشده»** ظاهر می‌شود.

1. تاریخ همان روز را انتخاب کنید (مثلاً دیروز).
2. دکمهٔ «ثبت گروهی …» را بزنید — همهٔ فیش‌های معطل یک‌جا انتخاب می‌شوند.
3. علت را ببینید و **ثبت** را بزنید.

| چه می‌شود | توضیح |
|-----------|-------|
| همان ردیف تبدیل می‌شود | ردیف دوم ساخته نمی‌شود؛ سابقهٔ تردد حفظ می‌شود |
| فیش واقعاً چاپ‌شده | دست نمی‌خورد — همچنان قفل است |
| گزارش تحویل | حالا آن افراد را نشان می‌دهد |
| چاپ فیزیکی | **هیچ** — ثبت در سامانه است |

برچسب ردیف هم عوض شد: به‌جای «دارای فیش این روز» می‌نویسد
**«در صف چاپ ماند — قابل ثبت دستی»**.
