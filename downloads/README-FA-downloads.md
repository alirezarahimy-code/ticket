## تیکت‌هایی که قبلاً اشتباه ارجاع شده‌اند

**خودکار جابه‌جا نمی‌شوند.** نسخهٔ ۱.۶۳.۱ فقط جلوی ارجاع‌های تازه را می‌گیرد.
برای اصلاح:

```bash
php tools/fix_ticket_assignments.php            # فقط نشان بده
php tools/fix_ticket_assignments.php --apply    # اعمال کن
php tools/fix_ticket_assignments.php --apply --ticket 123   # فقط یک تیکت
```

فقط تیکت‌های **باز** را می‌بیند. مسئولی که در فهرست کارشناسان هست (مثل علی)
رد می‌شود. هر تغییر در تاریخچهٔ تیکت ثبت می‌شود و همه‌چیز تراکنشی است.

شرح کامل: [CHANGE-REPORT-FA-1.63.1.md](https://github.com/alirezarahimy-code/ticket/blob/arena/22d4eba7-ticket/downloads/CHANGE-REPORT-FA-1.63.1.md)

## فیش‌های غذا برای روزهای گذشته

شام هر روز و ناهار پنجشنبه/جمعه/تعطیل رسمی خودکار ثبت می‌شوند — اما فقط **یک بار**،
در گذر پایان‌روز ساعت ۲۳ همان روز. هر شبی که Worker خاموش بوده، آن روز برای همیشه
خالی می‌ماند.

**دیگر لازم نیست دستی فیش بزنید.** در «تنظیمات سیستم ← اتصال پایگاه‌ها»، پایین صفحه،
کارت **«ثبت خودکار فیش روزهای گذشته»**: بازه را بدهید، «پیش‌نمایش» بزنید، بعد
«ثبت خودکار».

```bash
# یا از خط فرمان
php tools/backfill_food_auto_receipts.php --days 30             # فقط گزارش
php tools/backfill_food_auto_receipts.php --days 30 --apply     # ثبت واقعی
php tools/backfill_food_auto_receipts.php --from 2026-08-01 --to 2026-10-30 --apply
```

| قاعده | رفتار |
|-------|-------|
| ناهار فقط تعطیل | در روز کاری رد می‌شود |
| غیبت | کاربر غایب رد می‌شود |
| فیش واقعی چاپ‌شده | دست نمی‌خورد |
| اجرای دوباره | صفر ردیف تازه — بدون تکرار |
| چاپ فیزیکی | **هیچ** — فقط ثبت در سامانه |
| امروز | رد می‌شود؛ گذر شبانه پوشش می‌دهد |

بدون مهاجرت، بدون تغییر جدول، بدون مجوز تازه.

## یک هشدار صادقانه

هشدار کرون تا وقتی `register_system_alarm_tasks.bat` را اجرا نکنید باقی می‌ماند.
کد نمی‌تواند خودکار حلش کند: ثبت وظیفه در Windows Task Scheduler نیاز به دسترسی
مدیر ویندوز دارد و از داخل PHP صفحهٔ وب قابل انجام نیست. این **تنها** قدم دستی است.
