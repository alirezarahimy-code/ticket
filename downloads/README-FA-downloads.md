**۶۷ فایل، بدون مهاجرت، بدون تغییر جدول. — نسخهٔ r17**

**r17 — استخراج از راه SMB (همان روش TNI) و نامِ پاک:** سه ایراد استخراج
حل شد: ۱) دکمهٔ «استخراج محلی» حالا صریحاً «سرور سامانه» است؛ ۲) MAC آدرس
دیگر در ستون «نام» دیده نمی‌شود؛ ۳) مقصدی که DCOM/WinRM ردش کند، خودکار از
راه SMB خوانده می‌شود (کپی عامل روی C$ و اجرای SYSTEM). ابزار تشخیص تازه:
`tools/diag_extract.php`.

**r16 (همچنان در این بسته) — کار با هر دو پروتکل http و https:** یک چک‌باکس در
**تنظیمات ← اطلاعات سامانه**. HSTS هم از یک سال به ۵ دقیقه آمد تا مرورگر
دیگر قفل نشود.

**r15 سه ایراد تازه را هم بست** (بخش‌های ۸.۱۲ تا ۸.۱۴ گزارش):

| # | گزارش | ریشه |
|---|---|---|
| ۱ | «درخواست نامعتبر است. صفحه را تازه‌سازی کنید» | نشست ساخته‌شده زیر HTTPS با کوکی `Secure`؛ روی HTTP فرستاده نمی‌شود |
| ۲ | «با نام کاربری دامینی وارد نمی‌شوم» | LDAP خاموش / پسوند غیرفعال / آدرس خالی — همه پیام «رمز اشتباه» می‌گرفتند |
| ۳ | «هنوز `client 192.168.1.25` نشان می‌دهد» | نام واقعی ویندوز خوانده می‌شد ولی هرگز ذخیره نمی‌شد |


## تیکت‌هایی که قبلاً اشتباه ارجاع شده‌اند

**خودکار جابه‌جا نمی‌شوند.** نسخهٔ ۱.۶۳.۱ فقط جلوی ارجاع‌های تازه را می‌گیرد.
برای اصلاح:

```bash
php tools/fix_ticket_assignments.php            # فقط نشان بده
php tools/fix_ticket_assignments.php --apply    # اعمال کن
php tools/fix_ticket_assignments.php --apply --ticket 123   # فقط یک تیکت
```

فقط تیکت‌های **باز** را می‌بیند. مسئولی که در فهرست کارشناسان هست (مثل علی)
رد می‌شود. هر تغییر در تاریخچهٔ تیکت ثبت می‌شود و همه‌چیز تراکنشی است.

شرح کامل: [CHANGE-REPORT-FA-1.63.1.md](https://github.com/alirezarahimy-code/ticket/blob/arena/22d4eba7-ticket/downloads/CHANGE-REPORT-FA-1.63.1.md)

## فیش‌های غذا برای روزهای گذشته

شام هر روز و ناهار پنجشنبه/جمعه/تعطیل رسمی خودکار ثبت می‌شوند — اما فقط **یک بار**،
در گذر پایان‌روز ساعت ۲۳ همان روز. هر شبی که Worker خاموش بوده، آن روز برای همیشه
خالی می‌ماند.

**دیگر لازم نیست دستی فیش بزنید.** در «تنظیمات سیستم ← اتصال پایگاه‌ها»، پایین صفحه،
کارت **«ثبت خودکار فیش روزهای گذشته»**: بازه را بدهید، «پیش‌نمایش» بزنید، بعد
«ثبت خودکار».

```bash
# یا از خط فرمان
php tools/backfill_food_auto_receipts.php --days 30             # فقط گزارش
php tools/backfill_food_auto_receipts.php --days 30 --apply     # ثبت واقعی
php tools/backfill_food_auto_receipts.php --from 2026-08-01 --to 2026-10-30 --apply
```

| قاعده | رفتار |
|-------|-------|
| ناهار فقط تعطیل | در روز کاری رد می‌شود |
| غیبت | کاربر غایب رد می‌شود |
| فیش واقعی چاپ‌شده | دست نمی‌خورد |
| اجرای دوباره | صفر ردیف تازه — بدون تکرار |
| چاپ فیزیکی | **هیچ** — فقط ثبت در سامانه |
| امروز | رد می‌شود؛ گذر شبانه پوشش می‌دهد |

بدون مهاجرت، بدون تغییر جدول، بدون مجوز تازه.

## فیش‌هایی که در صف چاپ ماندند (پرینتر خراب بود)

اگر پرینتر خراب باشد، کارکنانی که تردد می‌زنند در صف چاپ می‌مانند — نه چاپ
می‌شوند، نه تحویل ثبت می‌شود. پیش از این، سامانه آن‌ها را «دارای فیش» می‌دانست و
راهی برای اصلاح نبود.

**اکنون:** در **ثبت تردد**، دکمهٔ **«ثبت گروهی N فیشِ چاپ‌نشده»** ظاهر می‌شود.

1. تاریخ همان روز را انتخاب کنید (مثلاً دیروز).
2. دکمهٔ «ثبت گروهی …» را بزنید — همهٔ فیش‌های معطل یک‌جا انتخاب می‌شوند.
3. علت را ببینید و **ثبت** را بزنید.

| چه می‌شود | توضیح |
|-----------|-------|
| همان ردیف تبدیل می‌شود | ردیف دوم ساخته نمی‌شود؛ سابقهٔ تردد حفظ می‌شود |
| فیش واقعاً چاپ‌شده | دست نمی‌خورد — همچنان قفل است |
| گزارش تحویل | حالا آن افراد را نشان می‌دهد |
| چاپ فیزیکی | **هیچ** — ثبت در سامانه است |

برچسب ردیف هم عوض شد: به‌جای «دارای فیش این روز» می‌نویسد
**«در صف چاپ ماند — قابل ثبت دستی»**.
