# معیار تحویل بسته‌های به‌روزرسانی

برای هر بسته‌ای که به کاربر تحویل می‌شود:

1. ZIP، فایل `.sha256` و گزارش نسخه باید در مخزن GitHub موجود باشند؛ صرف وجود محلی یا لینک به `main` پیش از انتشار کافی نیست.
2. لینک مستقیم دانلود باید به همان شاخه‌ای اشاره کند که فایل‌ها در آن push شده‌اند (`github.com/.../raw/refs/heads/<branch>/downloads/<package>.zip`) یا به asset پایدار یک GitHub Release.
3. پیش از ارائهٔ لینک، وجود ZIP و checksum روی GitHub، انطباق SHA-256 با فایل محلی، سلامت ZIP و مسیرهای صفحهٔ دانلود بررسی شود.
4. صفحهٔ دانلود نباید به شاخهٔ `main` یا Releaseای که فایل‌هایش هنوز آنجا نیستند اشاره کند. پس از ادغام در main می‌توان لینک پایدار main/Release را جایگزین کرد.
5. انتشار عمومی یا نصب روی سرور مقصد جدا از ساخت بسته است و فقط با درخواست صریح انجام می‌شود؛ تحویل یک بسته به‌تنهایی به معنی اجرای migration یا نصب آن نیست.

برای نسخهٔ ۱.۶۲.۷۳، لینک‌ها به شاخهٔ کاری `arena/642158e3-ticket` اشاره می‌کنند و بعد از push همین شاخه قابل دریافت خواهند بود.
