- نوع بسته: تجمیعی؛ اصلاحات قبلی ۱٫۶۳٫۴، CD/DVD، گزارش غایبین با دامنهٔ معاونت و این اصلاح شماره در یک بسته نگه داشته شده‌اند.

## اصلاح ثبت مجدد سریال CD/DVD

ریشهٔ مشکل این بود که رابط هنگام تایپ رقم‌های میانی، شمارهٔ موقت را نامعتبر تشخیص می‌داد و با پیشنهاد شمارهٔ بعدی جایگزین می‌کرد. اگر فیلد شماره خالی می‌رسید، اعتبارسنجی سرور هنگام ویرایش هم شمارهٔ آزاد بعدی را انتخاب می‌کرد؛ بنابراین ورود `009` می‌توانست `0021` و ویرایش بعدی `0022` ثبت کند.

- مقدار دستی هنگام تایپ حفظ و فیلد پنهان پیش از ارسال با مقدار نهایی همگام می‌شود.
- شمارهٔ کوتاه مانند `009` برای رسانهٔ ورودی، اگر سابقهٔ سریال داخلی `P86-0009` برای همان نوع رسانه موجود باشد، به همان سریال canonical تبدیل می‌شود. شناسهٔ بیرونی عددیِ بی‌سابقه به همان شکل می‌ماند.
- اختصاص خودکار شماره فقط برای ثبت جدید است؛ ویرایش خالی دیگر به شمارهٔ بعدی نمی‌پرد.
- ثبت/ویرایش روی سریال قدیم و جدید قفل می‌شود و بررسی وضعیت گردش حفظ است؛ ثبت دو ورود پیاپی یا دو خروج پیاپی همچنان رد می‌شود.
- شمارهٔ پیشنهادی، نسخهٔ cache اسکریپت را بالا می‌برد تا مرورگر نسخهٔ قدیمی را استفاده نکند.

## محتویات تجمیعی

تمام فایل‌های ۲۷گانهٔ manifest بستهٔ تجمیعی ۱٫۶۳٫۴-r7 حفظ شده‌اند. فایل‌های PHP/JavaScript و آزمون‌های CD/DVD با اصلاح نهایی هم‌تراز شده‌اند؛ فایل‌های version، release notes، README و گزارش نسخهٔ ۱٫۶۳٫۵ نیز افزوده شده‌اند. بستهٔ کامل شامل کل درخت فعلی برنامه و همهٔ مهاجرت‌های موجود است. بستهٔ به‌روزرسانی، مهاجرت‌های ۰۴۱ و ۰۴۲ را در manifest، پوشهٔ `migrations/` و `files/migrations/` حمل می‌کند.

## نتیجهٔ آزمون و محدودیت

- آزمون‌های هدفمند CD/DVD: **۱۲/۱۲ موفق**.
- بررسی نحوی JavaScript و PHP با parser: موفق؛ `git diff --check`: موفق.
- ZIP و checksum SHA-256، و hashهای فایل‌های manifest پس از ساخت دوباره بررسی می‌شوند.
- پایگاه‌داده و اجرای end-to-end ثبت واقعی رسانه در این محیط فراهم نبود؛ آزمون نهایی ثبت `CD / P86-0009` با آخرین گردش `OUT` باید در staging انجام شود. اگر آخرین گردش آن شماره `IN` باشد، ورود مجدد به‌درستی رد می‌شود.

پیش از نصب نسخهٔ پشتیبان بگیرید. فایل‌های `config.php` و `storage/` در بستهٔ کامل قرار نمی‌گیرند.
