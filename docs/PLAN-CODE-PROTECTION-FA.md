# برنامهٔ آتی: دشوارکردن خواندن و کپی‌برداری از سورس

**وضعیت:** ثبت شد؛ هنوز اجرا نشده است.

## هدف و محدودیت

هدف جلوگیری صددرصدی نیست؛ هدف این است که خواندن و استفادهٔ مجدد از کد آن‌قدر زمان‌بر/پرهزینه شود که کپی‌برداری صرفه نداشته باشد. چون سامانه آفلاین و روی سرور محلی شرکت اجرا می‌شود، مدیر سرور همچنان می‌تواند فایل‌های نصب‌شده را کپی کند و در نهایت روش‌های محافظتی را دور بزند. این محدودیت باید در تصمیم نهایی لحاظ شود.

## مسیر پیشنهادی برای بررسی و اجرا

1. **سورس اصلی را دست‌نخورده نگه دارید** و نسخهٔ انتشار محافظت‌شده را در مسیر/پوشهٔ build جدا بسازید؛ هیچ obfuscation یا encoding مستقیمی روی working tree یا سورس اصلی انجام نشود.
2. **JavaScript/CSS مرورگر:** برای build انتشار، minify و در صورت نیاز obfuscate کنید و source map منتشر نکنید. این کار فقط خواندن را دشوارتر می‌کند؛ فایل‌های تحویلی مرورگر همچنان قابل ذخیره و کپی‌اند.
3. **PHP سرور:** پیش از انتخاب encoder، نسخهٔ واقعی PHP در XAMPP مقصد و امکان نصب loader آفلاین بررسی شود. سپس سازگاری encoder تجاری مانند ionCube یا SourceGuardian ارزیابی شود. encoder تضمین ضدکپی نیست و بستهٔ رمزگذاری‌شده نیز قابل کپی است.
4. **مجوز آفلاین دوره‌ای، فقط با تأیید روشن مدیریت:** در صورت تصویب، راهکار باید بر امضای دیجیتال و کلید خصوصی خارج از سرور تکیه کند، نه رمز مشترک/قابل استخراج داخل سورس. چالش باید به همان نصب وابسته باشد. مدت اعتبار، شیوهٔ تمدید و مسئولین بازیابی باید از قبل مشخص شوند.
5. از قفل پنهان، خاموشی ناگهانی، حذف/قفل‌کردن داده یا وابستگی تمدید به یک نفر استفاده نشود. اگر مجوز منقضی شد، هشدار و مهلت تنفس، دسترسی مشاهده/خروجی داده و مسیر بازیابیِ موردتوافق لازم است.
6. **رمزگذاری بکاپ جدا از محافظت سورس زنده است.** با مدیریت باید روش نگهداری کلید و بازیابی بکاپ توافق و بازیابی روی نسخهٔ جداگانه آزمایش شود.
7. قبل از هر build محافظت‌شده، فهرست فایل‌های قابل توزیع، نصب تمیز آفلاین، سازگاری PHP/افزونه‌ها و راه برگشت بررسی شود. تغییرات موجود در workspace حفظ شوند.

## پیش‌نیازهای نوبت اجرا

- دریافت خروجی `php -v` از XAMPP واقعی مقصد و فهرست افزونه‌های PHP لازم.
- تصمیم مدیریت دربارهٔ encoder/loader، مالک کلید مجوز، مدت تمدید، grace period و فرآیند بازیابی.
- ساخت کپی staging جدا از سورس و حفظ نسخهٔ اصلی/بکاپ.
- محدودیت آزمون جاری: آزمون‌های تیکت، CD/DVD و inventory اجرا نشوند؛ فقط آزمون‌های مدیریت/سفارش غذا مجازند.

## معیار پذیرش

- سورس اصلی حفظ شده و package انتشار جداگانه تولید شود.
- package در محیط آفلاین و با PHP/loader مقصد اجرا شود.
- مرورگر source map نگیرد؛ پذیرفته شود که JavaScript همچنان قابل کپی است.
- مسیر تمدید/بازیابی مجوز و بازیابی بکاپ مستند و با مدیریت توافق شده باشد.
- هیچ رفتار پنهان یا توقف ناگهانی/از‌دست‌رفتن داده ایجاد نشود.
