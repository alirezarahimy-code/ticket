## شواهد اجرایی (اجراشده)
- `php -l` روی همهٔ فایل‌های PHP بسته: صفر خطا.
- ادغام روی ۱.۶۲.۹۴: `test_access_coverage_offline.php` = ۵۴ موفق / ۰ ناموفق؛ `test_ticket_txn_offline.php` = بدون شکست.
- MariaDB 10.11.14، دیتابیس ساخته‌شده از `install-empty-db.sql` ۱.۶۲.۹۴ (حالت پیش از ۰۳۵):
  - اجرای ۰۳۵ دو بار پشت‌سرهم: موفق و idempotent؛ ENUM شامل `rejected`، ستون `rejected_at`، جدول نوبت‌ها، ۱۶ دستهٔ پیش‌فرض.
  - دستهٔ موجود با `code` مشابه (نام سفارشی + غیرفعال) بازنویسی نشد.
  - نبودِ پیش‌نیاز ۰۳۶: اجرا با خطای ۱۱۴۶ `RC_PREREQUISITE_MISSING__apply_food_036_first` پیش از هر تغییر متوقف شد.
  - اسکریپت rollback: روی DB تمیز ENUM و جدول را برگرداند؛ با تیکت `rejected` یا نوبت ثبت‌شده، پیام ABORT داد و هیچ تغییری نداد.
- راه‌اندازی زنده: درخت ادغام‌شده (۱.۶۲.۹۴ + بسته) روی `php -S` با MariaDB 10.11 (نصب تازه از `install-empty-db.sql` بسته + اجرای ۰۳۵):
  - ورود ادمین، سپس GET موفق (۲۰۰) برای: خانهٔ مرکز، ثبت درخواست، صف، گزارش‌ها، فضای ادمین، تقویم، فضای سوپروایزر، خدمات، تحلیل، اعلان‌ها؛ مسیر ناشناخته ۴۰۴؛ هیچ Warning/Notice/Fatal در لاگ.
  - منوی ماژول شامل «بازگشت به سامانهٔ اصلی» و «اعلان‌ها» است؛ ماه جاری تقویم شمسی نمایش داده می‌شود (۱۴۰۵-۰۸).
  - `create_ticket` واقعی: پیش از اصلاح ۶ شکست خورد؛ پس از آن موفق (شمارهٔ `SUP-00002`، ریدایرکت به جزئیات). شمارهٔ `SUP-00001` از تلاش ناموفق قبلی مصرف‌شده می‌ماند (طراحی عمدی: شمارهٔ رزروشده دوباره استفاده نمی‌شود).
  - ثبت گروهی نوبت: معتبر ← ثبت؛ CSRF نادرست ← ۴۱۹؛ بازهٔ متداخل و زمان پایان قبل از شروع ← رد کل دسته با پیام فارسی؛ فقط یک ردیف در جدول.

## اجرا نشده / همچنان نیازمند آزمون شما
1. MariaDB 10.4 (XAMPP) و MySQL 8 — فقط 10.11 آزموده شد.
2. ظاهر بصری، تم و دارک‌مود در مرورگر (خروجی HTML بررسی شد، نه رندر بصری).
3. مسیر POST تقویم (`?calendar=1`) از `post_context_begin()` عبور نمی‌کند (بدون لاگ عملیات مشترک و `post_action_failed`)؛ CSRF و مجوز دارد. تغییر آن بازطراحی است و در r3 انجام نشد.
4. تغییرات خارج از قلمرو ظاهری: `choose_handling_agent` (حذف مدیران چارت از ارجاع خودکار)، `lib/auth-scope.php` (دید مدیر واحد)، `cron/sla_maintenance.php`، `cron/ticket_auto_close.php` — تصمیم مالک است ولی با DB واقعی و تست دسترسی باید سنجیده شود.
5. تناقض تصمیم‌ها: بازگشت ورودی‌های RC به سامانهٔ اصلی (۲۰۲۶-۱۱-۱۰) در برابر استقلال کامل — نیازمند تأیید صریح مالک.
6. ثبت مهاجرت در `schema_updates` فقط با نام فایل است؛ اگر ۰۳۵ قبلاً (حتی دستی) ثبت شده باشد نصاب آن را رد می‌کند. قبل از نصب: `SELECT * FROM schema_updates WHERE migration LIKE '035%';`
7. گیت‌های قرمز گزارش‌شده (T07، Logging، ۸۵ شکست ایستا، ۲ شکست `test_route_security_static`) در r3 بررسی نشدند.
