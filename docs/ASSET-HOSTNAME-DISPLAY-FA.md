# نام کامپیوتر در شناسنامه — راهنمای کامل

**نسخه:** ۱.۶۳.۱ · **موضوع:** چرا نام سیستم IP نشان می‌داد و چطور برای همیشه درست شد

---

## ۱) مشکلی که دیده شد

در کمبوی **«سیستم مرتبط»** فرم ثبت تیکت و در فهرست شناسنامه‌ها، جای نام
کامپیوتر این دیده می‌شد:

```
clint 192.168.1.65
```

نه اسم کامپیوتر، نه چیزی که کاربر بتواند با برچسب روی کیس تطبیق دهد.

### چرا مهم بود

۱. **ظاهر:** شناسنامه‌ها باید تمیز باشند، نه پر از آدرس IP.
۲. **ثبت تیکت:** برای همهٔ خدمات IT انتخاب «سیستم مرتبط» الزامی است.
   کاربر باید سیستمی را انتخاب کند که اسمش روی برچسب کیس نوشته شده.
   هیچ کاربری IP خودش را نمی‌داند — پس این فهرست قابل استفاده نبود.

---

## ۲) ریشهٔ واقعی

سه چیز هم‌زمان:

| # | ریشه | نتیجه |
|---|---|---|
| ۱ | reverse DNS روی شبکهٔ شما برای کلاینت‌ها نامی مثل `clint 192.168.1.65` برمی‌گرداند (اسم + IP در یک فیلد) | همین مقدار در `assets.hostname` ذخیره شد |
| ۲ | قاعدهٔ نمایش قدیمی هر چیزی بعد از **اولین نقطه** را «دامنه» حساب می‌کرد | `clint 192.168.1.65` می‌شد `clint 192` — نه اسم، نه IP |
| ۳ | رکوردهایی که فقط IP داشتند (`CLIENT-192-168-1-65`) | رشتهٔ خط‌تیره‌ای بی‌معنا نمایش داده می‌شد |

مورد دوم بدترین بود: نمایش از خودِ مقدار خام **گمراه‌کننده‌تر** می‌شد.

---

## ۳) راه‌حل — دو لایه

### لایهٔ ۱: نمایش (بدون تغییر داده)

قاعدهٔ نمایش بازنویسی شد: **اول IP از رشته برداشته می‌شود، بعد قاعدهٔ دامنه
اعمال می‌شود.**

```
clint 192.168.1.65          → clint
clint-192.168.1.65          → clint
clint 192.168.1.65.corp.local → clint
CLIENT 192.168.1.65         → client
pc1 10.1.2.3                → pc1
pc1 192.168.1.5 CORP        → pc1
```

**چیزهایی که دست‌نخورده می‌مانند:**

```
reza-pc                     → reza-pc
ADMINIT2.DOMAIN.LOCAL       → adminit2     (قاعدهٔ دامنه همچنان کار می‌کند)
DOMAIN-ADMINIT2             → adminit2
ADMINIT2$                   → adminit2
```

**آدرس IP خالص** (وقتی تنها شناسهٔ موجود است) هم دست‌نخورده می‌ماند — چون
نام واقعی ندارد و پاک‌کردنش یعنی از دست دادن تنها شناسه.

#### IP در «پس‌زمینه» باقی می‌ماند

کاربر گفت: «تو پس‌زمینه به هر شکل باشد ایرادی ندارد». دقیقاً همین شد:

- **راهنمای ماوس (tooltip):** نام کامل `clint 192.168.1.65` روی نام نمایش داده می‌شود.
- **جستجو:** تایپ IP یا نام کامل، رکورد را پیدا می‌کند.
- **ستون IP:** آدرس IP جدا و کامل در فهرست شناسنامه‌ها هست.

هیچ اطلاعاتی گم نشد؛ فقط از متن اصلی برداشته شد.

### لایهٔ ۲: ابزار تعمیر برای رکوردهای موجود

نمایش درست، داده را عوض نمی‌کند. برای پاک‌کردن دائمی نام‌های ثبت‌شده:

```powershell
php tools\normalize_asset_hostnames.php           # فقط گزارش
php tools\normalize_asset_hostnames.php --apply   # اعمال
```

خروجی نمونه:

```
  رکوردهای بررسی‌شده : 12
  قابل پاک‌سازی      : 4
  فقط IP (رها می‌شود) : 1

  شناسه نام کنونی                    نام تازه
  10     clint 192.168.1.65           clint
  11     PC1 10.1.2.3                 PC1
  12     DOMAIN-ADMINIT2              ADMINIT2

  ⚠️  این رکوردها فقط IP دارند و نام واقعی ندارند — دستی نام‌گذاری شوند:
     شناسه 13     IP: 192.168.1.99     شناسهٔ رکورد: T3
```

**نکتهٔ مهم:** ابزار رکوردی را که فقط IP است **دست نمی‌زند** و هشدار می‌دهد.
آن رکوردها باید از برچسب کیس یا با اجرای اسکن دامنه نام بگیرند.

## ۴) یک باگ دیگر که همان‌جا پیدا شد

`hostname_key` — کلید تشخیص تکراری — پس از **تغییر نام** به‌روز نمی‌شد.

نتیجه: اگر نام سیستم را ویرایش می‌کردید و بعد همان سیستم دوباره از دامنه
اسکن می‌شد، سامانه فکر می‌کرد سیستم تازه‌ای است و **رکورد تکراری** می‌ساخت.

این در ۶ نقطه رفع شد:

| فایل | نقطه |
|---|---|
| `actions/asset-actions.php` | ذخیرهٔ فرم شناسنامه |
| `inventory.php` | ۴ نقطهٔ به‌روزرسانی خودکار کلاینت/سرور |
| `domain-scan.php` | ثبت و به‌روزرسانی از اسکن دامنه |

حالا کلید هویت **همیشه** همراه با نام عوض می‌شود.

## ۶) اگر نام روی کیس چیز دیگری است

نام نمایشی فقط `clint` است — همان چیزی که سامانه می‌دانست. اگر برچسب روی کیس
چیز دیگریست (مثلاً `CLINT-ADMIN-07`)، نام درست را یک‌بار در شناسنامه وارد کنید:

```
شناسنامه رایانه ← «تکمیل دستی» ← فیلد «نام کامپیوتر»
```

از آن به بعد، همان نام در همهٔ فهرست‌ها و کمبوها نمایش داده می‌شود و کلید
هویت هم به‌طور خودکار به‌روز می‌شود.

برای اصلاح گروهی، اسکن دامنه نام واقعی را از سیستم می‌خواند و جایگزین می‌کند.
