# گزارش تغییرات Logging — نسخه 1.62.76

## مبنا و محدوده

- Base دقیق: Full Source نسخه `1.62.75`.
- Target: نسخه `1.62.76`.
- هدف: اصلاح صحت ثبت، تکمیل فراداده، طبقه‌بندی و ردیابی بین‌ماژولی؛ بدون بازنویسی معماری و بدون تغییرات ظاهری غیرضروری.
- هیچ تغییری روی Production یا Staging مقصد انجام نشده است.
- Migration جدید دیتابیس لازم نیست؛ ستون‌های `module`، `target_type`، `target_id`، `target_label` و فیلدهای Logging مورد استفاده در Base 1.62.75 موجودند.

## اصلاحات پیاده‌سازی‌شده

1. **Circuit Breaker و Audit موفق:** اگر دیتابیس در حالت Circuit Open باشد و عملیات کسب‌وکار داخل تراکنش فعال قرار داشته باشد، رویداد Audit با نتیجه `success` دیگر به Spool مستقل منتقل نمی‌شود. ثبت با خطا متوقف می‌شود تا `save_audit_required()` تراکنش عملیات را fail-closed کند. رخدادهای `failure` و `denied` همچنان می‌توانند مستقل و با حذف FK نامعتبر به Spool بروند.
2. **تکمیل context حسابرسی:** تابع مرکزی `activity_audit_context()` برای عملیات Audit ماژول، نوع هدف، شناسه و برچسب هدف را از قرارداد اکشن/فراداده استخراج می‌کند. این رفتار برای `save_audit_required()` و `save_audit()` یکسان شده است.
3. **پوشش Holiday:** ایجاد، فعال‌سازی، غیرفعال‌سازی، حذف و ورود گروهی تعطیلات با Audit اجباری در همان تراکنش ثبت می‌شوند. برای تغییر/حذف رکورد موجود از `SELECT ... FOR UPDATE` استفاده شده است؛ هر چهار مسیر Commit نیز از `db_commit()` محافظت‌شده استفاده می‌کنند تا نتیجهٔ ناموفق Commit به‌عنوان موفقیت گزارش نشود.
4. **تکمیل Allowlist:** فراداده‌های CD/DVD، Change/Problem/CAB، Ticket، Holiday و سایر زمینه‌های عملیاتی مشخص‌شده حفظ می‌شوند؛ `logging_sensitive_key()` همچنان برای پالایش داده حساس اعمال می‌شود.
5. **طبقه‌بندی رویدادها:** کدهای CD/DVD، Holiday، چرخه Change و Problem، تصمیم CAB، اتصال Ticket به Governance، LDAP و Profile نگاشت صریح دارند.
6. **اصلاح تب مدیریتی:** شرط گسترده مبتنی بر `module IS NULL` حذف شد تا رویدادهای قدیمی با Module خالی، صرفاً به علت خالی‌بودن Module وارد فهرست مدیریتی نشوند. دسته Audit و اکشن‌های مدیریتی شناخته‌شده مبنای فیلتر هستند.
7. **تکمیل تاریخچه Ticket:** جست‌وجوی نوع رخداد، وضعیت، جزئیات و عامل افزوده شد؛ جزئیات قابل‌نمایش بر اساس سطح دسترسی پالایش می‌شوند؛ صفحه‌بندی ۱۰۰ رخداد در هر صفحه و شناسه‌های Request/Trace برای کارکنان افزوده شد.
8. **آزمون رگرسیون جدید:** آزمون مستقل تراکنش Audit، جلوگیری از Spool موفقیت در Circuit Open، نگاشت Module/Target، حفظ Allowlist و پالایش رازها افزوده شد.

## رفتار تراکنش

در مسیر عادی، درج `activity_logs` با همان PDO و تراکنش کسب‌وکار انجام می‌شود؛ بنابراین Rollback کسب‌وکار، ردیف Audit موفق را نیز Rollback می‌کند. مسیر Spool مستقل فقط برای رخدادهایی مجاز است که نباید با Rollback عملیات کسب‌وکار از بین بروند، مانند `failure` و `denied`. در Circuit Open، موفقیت Audit داخل تراکنش به‌جای Spool مستقل، fail-closed می‌شود.

## محدودیت‌های پذیرش

- MySQL/MariaDB واقعی در این محیط اجرا نشد؛ `pdo_mysql` نصب نیست و DNS مخازن Debian در دسترس نبود.
- Windows Server، NTFS ACL، IIS AppPool، Task Scheduler و Clone/Staging مقصد در این محیط اجرا نشدند.
- آزمون‌های آفلاین PHP/Python، جایگزین Integration واقعی دیتابیس و پذیرش محیط مقصد نیستند.

**نتیجه:** اصلاحات کد در Working Copy مستقل اعمال شده‌اند؛ نسخه برای بازبینی بسته و پایلوت کنترل‌شده آماده می‌شود، اما Production تأیید نشده است.
