# راهنمای نصب بستهٔ تکمیلی ۱.۶۳.۱-r20

این بسته، روی پایهٔ ۱.۶۳ به‌روزرسانی تجمعی است؛ فایل‌های اصلاحات قبلی r19 را هم حفظ می‌کند و فایل‌های لازم برای شناسنامه/استخراج و اصلاح پاک‌سازی TENTER را در بر دارد. اگر سامانه از قبل ۱.۶۳.۱ است، از همین بسته برای هم‌ترازکردن فایل‌ها استفاده کنید.

## پیش از نصب

1. از پوشهٔ نصب نسخهٔ پشتیبان بگیرید.
2. از دیتابیس MySQL/MariaDB خروجی بگیرید.
3. فایل ZIP را باز کنید و **محتویات پوشهٔ `files/`** را روی ریشهٔ نصب سامانه کپی کنید؛ خود پوشهٔ `files/` را داخل سامانه کپی نکنید.
4. `config.php`، فایل‌های `.env` و داده‌های واقعی `storage/` و `uploads/` را جایگزین یا حذف نکنید.
5. بعد از کپی، مقدار `VERSION` باید `1.63.1` باشد.

این بسته مهاجرت دیتابیس ندارد؛ کد شناسنامه از ستون `hostname_key` موجود در پایهٔ ۱.۶۳ استفاده می‌کند. هیچ ادغام یا حذف تکراریِ شناسنامه‌ای خودکار اجرا نمی‌شود.

## فایل‌های تکمیلی که در بسته هستند

- ابزارهای استخراج: `tools/collect_server_inventory.ps1`، `tools/collect_via_smb.ps1` و `tools/diag_extract.php` به‌همراه دو فایل اجرای تشخیص.
- وابستگی لازم ابزار ادغام شناسنامه: `lib/asset-dedupe.php` در کنار `tools/asset_dedupe.php`.
- اصلاحات جاری هویت، ورود موجودی، نمایش نام و استخراج شبکه.
- اصلاح شرط حذف ردیف مصرف‌شده از TENTER و ابزار تشخیص/پاک‌سازی ردیف‌های باقی‌مانده: `tools/repair_source_rows.php`.
- آزمون‌های آفلاین و آزمون SQLite موجود در `tools/` و `tests/`.

## آزمون‌های بدون تغییر داده

از ریشهٔ نصب و با PHP خط فرمان اجرا کنید:

```cmd
php tools\test_source_delete_offline.php
php tools\test_source_time_delete_offline.php
php tools\test_asset_dedupe_offline.php
php tools\test_asset_names_offline.php
php tests\test_asset_inventory_flow_sqlite.php
```

آزمون SQLite به افزونهٔ `pdo_sqlite` نیاز دارد. این آزمون‌ها کد و SQL را بررسی می‌کنند؛ موفقیت آن‌ها به‌تنهایی تأیید اتصال SMB/WinRM یا ping به رایانه‌های شبکه نیست. برای بررسی اتصال مقصد، از راهنمای `docs/DIAG-EXTRACT-COMMANDS-FA.md` و `docs/ASSET-IDENTITY-AND-LIVE-TEST-FA.md` استفاده کنید.

## پاک‌سازی ردیف‌های قدیمی TENTER

اصلاح کد جلوی جا ماندن ردیف‌های بعدی را می‌گیرد؛ ردیف‌هایی که قبلاً در فایل Access باقی مانده‌اند خودبه‌خود پاک نمی‌شوند. ابتدا فقط گزارش بگیرید:

```cmd
php tools\repair_source_rows.php
```

گزارش را بررسی کنید. اگر ردیف‌های شناسایی‌شده واقعاً مصرف‌شده‌اند، در زمان نگهداری و پس از توقف Worker، پاک‌سازی واقعی را اجرا کنید:

```cmd
php tools\repair_source_rows.php --apply
```

پیش‌فرض ابزار فقط گزارش است. `--apply` فایل Access را تغییر می‌دهد؛ بدون بررسی خروجی و نسخهٔ پشتیبان اجرا نکنید.

## پاک‌سازی شناسنامه‌های تکراری

`tools/asset_dedupe.php` نیز پیش‌فرض فقط گزارش می‌دهد. **`--apply` را اجرا نکنید** مگر اینکه گزارش بررسی شده و از دیتابیس نسخهٔ پشتیبان گرفته باشید. اصلاح هویت/ورود موجودی به‌تنهایی رکوردهای تکراری را حذف نمی‌کند.
