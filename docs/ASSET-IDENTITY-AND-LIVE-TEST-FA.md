# هویت شناسنامه، به‌روزرسانی قطعه و آزمون شبکه

## هویت اصلی رایانه

سامانه **MAC را کلید اصلی نمی‌گیرد**. ترتیب تشخیص اکنون چنین است:

1. سریال معتبر دستگاه (شناسهٔ اول)
2. MAC معتبرِ unicast (جایگزین؛ اگر سریال پیدا نشد یا معتبر نبود)
3. نام رایانه (آخرین جایگزین)

IP در هیچ‌یک از این هویت‌ها نیست. MACهای صفر، broadcast، multicast و ورودی‌های غیر MAC رد می‌شوند. اگر MAC مشترک به چند رکورد با سریال‌های معتبر و متعارض برسد، ابزار پاک‌سازی آن‌ها را خودکار ادغام نمی‌کند؛ شناسه و نام رکوردها را برای بررسی گزارش می‌دهد.

درج تازهٔ موجودی سرور و API عامل نیز از یک تابع مشترک برای ترتیب پارامترها استفاده می‌کنند؛ hostname دوبار bind نمی‌شود.

## تعویض قطعه و حفظ داده

هر برداشت موفق، **تمام فیلدهای ماشینی‌ای را که در همان برداشت با موفقیت جمع شده‌اند** تازه می‌کند؛ فقط قطعهٔ تعویض‌شده به‌طور مصنوعی محدود نمی‌شود. اگر پرس‌وجوی یک دسته شکست بخورد یا آن دسته در روش جاری اصلاً خوانده نشود، دادهٔ قبلی آن دسته حفظ می‌شود. مالک، واحد، پلاک و اطلاعات سازمانی جدا از دادهٔ استخراج ماشینی‌اند و این مسیر آن‌ها را بازنویسی نمی‌کند. برداشت تازه نیز در تاریخچه می‌ماند.

## نامی که کاربر می‌بیند

گزینهٔ «سیستم مرتبط» در فرم درخواست، فهرست سیستم‌ها و عنوان شناسنامه فقط نام نمایشی رایانه را نشان می‌دهند؛ تگ/شناسه به متن نام چسبانده نمی‌شود. اطلاعات تگ همچنان برای جست‌وجو و فیلد شناسهٔ شناسنامه در دسترس است.

## مسیر برداشت خودِ سرور سامانه

دکمهٔ جداگانهٔ «استخراج محلی سرور سامانه» از فهرست و جزئیات دارایی حذف شده است؛ چون رکورد سرور در همان فهرست سیستم‌هاست. اگر سرور پنل Windows است، آن را در فهرست انتخاب و «استخراج اطلاعات سیستم‌های انتخاب‌شده» را اجرا کنید. مسیر معمول، نام میزبان محلی را تشخیص می‌دهد و برای آن PowerShell را روی میزبان PHP اجرا می‌کند، نه از راه دور.

فرم برداشت انتخابی همچنان الزام می‌کند نام کاربری و رمز برای همان نوبت وارد شوند. برای میزبان محلی، این اعتبارنامه‌ها به PowerShell محلی تحویل داده نمی‌شوند؛ اجرای محلی با حساب سرویس وب انجام می‌شود. برای رایانهٔ راه‌دور، همان اعتبارنامه‌ها در نشست CIM/WMI/WinRM مصرف می‌شوند. اکشن قدیمی `collect_inventory` در backend باقی مانده، ولی دکمهٔ مستقلی برای آن در UI نمایش داده نمی‌شود.

## آزمون‌هایی که در محیط کد اجرا شدند

دستور آزمون integration:

```text
php tests/test_asset_inventory_flow_sqlite.php
```

این آزمون PHP و SQL واقعی برنامه را روی SQLite درون‌حافظه‌ای اجرا می‌کند: درج واقعی مسیر upsert، درج SQL مسیر API، به‌روزرسانی برداشت دوم و سوم، حفظ RAM قبلی در شکست پرس‌وجو، نگاشت MAC/سریال، حفظ فیلدهای اداری، و probe واقعی TCP/ICMP به loopback sandbox. دادهٔ سخت‌افزارِ نمونه از همان mapper تولید می‌شود، اما خروجی از رایانهٔ ویندوزی واقعی نیامده است.

آزمون منطق هویت و ادغام:

```text
php tools/test_asset_dedupe_offline.php
```

این آزمون همان تابع گروه‌بندی‌ای را اجرا می‌کند که ابزار پاک‌سازی استفاده می‌کند؛ شامل سناریوی عددی ۱۲۵ ردیف و ۳۶ جفت تکراری که خروجی محاسباتی آن ۸۹ ردیف است. این سناریو **دادهٔ ۸۹ رایانهٔ واقعی شما نیست** و نباید نتیجهٔ شمارش واقعی تلقی شود.

نتیجهٔ آخرین اجرا در sandbox: integration برابر ۲۵/۲۵، منطق dedupe برابر ۳۵/۳۵، استخراج آفلاین ۳۱/۳۱، شناسنامه ۱۸/۱۸، نام نمایشی ۵۰/۵۰ و آزمون‌های ایستای مرتبط ۱۵/۱۵ موفق بودند. همهٔ فایل‌های PHP تغییرکرده نیز lint شدند.

پینگ موفق loopback فقط نشان می‌دهد خود probe در محیط اجرا کار می‌کند؛ تأیید نمی‌کند که مقصدهای شبکهٔ شما ping می‌شوند یا استخراج Windows موفق است.

## اجرای آزمون روی XAMPP / Windows Server 2016

پس از نصب نسخهٔ شامل این فایل‌ها، PowerShell را روی سرور XAMPP باز و این بلوک را اجرا کنید. مسیر پیش‌فرض PHP، `C:\xampp\php\php.exe` است؛ اسکریپت آزمون را زیر `C:\xampp\htdocs` پیدا می‌کند:

```powershell
$php = 'C:\xampp\php\php.exe'
$test = Get-ChildItem -Path 'C:\xampp\htdocs' -Filter 'test_asset_inventory_flow_sqlite.php' -File -Recurse |
    Where-Object { $_.Directory.Name -eq 'tests' } |
    Select-Object -First 1
if (-not $test) { throw 'tests\test_asset_inventory_flow_sqlite.php زیر C:\xampp\htdocs پیدا نشد.' }
$appRoot = $test.Directory.Parent.FullName
& $php (Join-Path $appRoot 'tests\test_asset_inventory_flow_sqlite.php')
if ($LASTEXITCODE -ne 0) { throw "آزمون integration شکست خورد (exit $LASTEXITCODE)." }
& $php (Join-Path $appRoot 'tools\test_asset_dedupe_offline.php')
if ($LASTEXITCODE -ne 0) { throw "آزمون هویت/ادغام شکست خورد (exit $LASTEXITCODE)." }
```

اگر `pdo_sqlite` در PHP خطای نبود extension داد، در `C:\xampp\php\php.ini` فعال‌بودن `pdo_sqlite` را بررسی کنید. این مرحله SQLite را می‌آزماید، نه MySQL واقعی برنامه.

برای دیدن شمارش واقعی تکراری‌ها در MySQL نصب‌شده، این بلوک فقط‌گزارش را اجرا می‌کند و هیچ تغییری نمی‌دهد:

```powershell
$php = 'C:\xampp\php\php.exe'
$dedupe = Get-ChildItem -Path 'C:\xampp\htdocs' -Filter 'asset_dedupe.php' -File -Recurse |
    Where-Object { $_.Directory.Name -eq 'tools' } |
    Select-Object -First 1
if (-not $dedupe) { throw 'tools\asset_dedupe.php زیر C:\xampp\htdocs پیدا نشد.' }
& $php $dedupe.FullName
if ($LASTEXITCODE -ne 0) { throw "گزارش تکراری‌ها اجرا نشد (exit $LASTEXITCODE)." }
```

خروجی این دستور برای تصمیم دربارهٔ دادهٔ واقعی لازم است. گزینهٔ `--apply` را اجرا نکنید مگر گزارش را بررسی کرده و از دیتابیس پشتیبان گرفته باشید.

برای آزمون **مقصد واقعی** از خود رابط برنامه روی همان سرور استفاده کنید:

1. `index.php?page=assets` را باز کنید و فقط یک رایانه را انتخاب کنید.
2. برای «آزمون حساب روی یک سیستم» نام کاربری/رمز را در همان فرم وارد کنید؛ رمز را در چت یا دستور پوسته نفرستید. این آزمون استخراج WMI/WinRM را می‌سنجد و چیزی در شناسنامه ذخیره نمی‌کند.
3. سپس همان یک رایانه را برای «استخراج اطلاعات سیستم‌های انتخاب‌شده» اجرا کنید تا مسیر ذخیره و در صورت نیاز fallback شبکه نیز واقعاً آزموده شود.
4. از «فقط پینگ انتخاب‌شده‌ها» فقط برای آزمون reachability استفاده کنید. آنلاین‌بودن (ICMP/TCP) به‌تنهایی اثبات دسترسی WMI/WinRM/SMB یا موفقیت استخراج نیست.
5. پس از برداشت موفق، صفحهٔ همان شناسنامه و تاریخچه را بررسی کنید؛ سپس می‌توانید برداشت را برای بقیهٔ فهرست ادامه دهید.

**مرز آزمون این شاخه:** از sandbox فعلی به Windows Server 2016، دیتابیس MySQL نصب شما یا ۸۹ مقصد واقعی دسترسی اجرایی نداریم. بنابراین نه استخراج مقصد واقعی اجرا شده و نه شمارش/عدم‌تکرار دادهٔ واقعی شما تأیید شده است. برای چنین ادعایی، باید مراحل مقصد واقعی بالا روی همان سرور اجرا شوند؛ این محدودیت را با تست loopback یا SQLite نمی‌توان جایگزین کرد.
