# Runbook بازگشت — 1.62.76 به 1.62.75

## پیش‌شرط

- بسته Update فقط روی Base دقیق 1.62.75 اجرا می‌شود.
- این انتشار Migration جدید ندارد؛ بنابراین Rollback نیازمند بازگشت Schema نیست.
- پیش از ارتقا، Snapshot مستقل فایل‌ها و Backup قابل‌بازیابی دیتابیس تهیه شود.

## بازگشت

1. Task Scheduler و Workerهای Logging را موقتاً متوقف کنید.
2. درخواست‌های وب را در پنجره نگهداری متوقف یا به صفحه تعمیر هدایت کنید.
3. فایل‌های Delta نسخه 1.62.76 را با فایل‌های Full Source/Backup نسخه 1.62.75 جایگزین کنید؛ فایل‌های `config.php`، `storage/` و `uploads/` را از Backup سالم و هم‌زمان بازیابی کنید.
4. چون Migration جدیدی اجرا نشده، Schema به 1.62.75 برمی‌گردد؛ جدول‌های لاگ و Spool را حذف نکنید.
5. Permission/ACL را فقط با Backup/Runbook مقصد و تأیید مدیر Windows بازبینی کنید.
6. Workerها را راه‌اندازی و سلامت Logging، تعداد صف و Dead Letter را کنترل کنید.
7. نتیجه و زمان Rollback را در گزارش تغییر ثبت کنید.

**هشدار:** حذف یا پاک‌سازی Spool/Dead Letter هنگام Rollback ممنوع است؛ ممکن است رخدادهای ثبت‌نشده در DB در آن باقی مانده باشند.
