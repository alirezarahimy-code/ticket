# دستور اجرای دقیق — تشخیص مشکل استخراج شناسنامه (XAMPP)

**نسخه:** ۱.۶۳.۱-r17-ج · **فایل:** `tools/diag_extract.php`

این ابزار هیچ چیزی را تغییر نمی‌دهد. فقط می‌خواند و می‌گوید کدام شرط شکسته است.

> **اگر با XAMPP کار می‌کنید، این سند را کامل بخوانید.** سه فرض سند قدیمی روی XAMPP غلط بود و همه اصلاح شده‌اند.

---

## تفاوت XAMPP با IIS — چرا مهم است

روی IIS، PHP زیر `ApplicationPoolIdentity` اجرا می‌شود: حساب ماشین، بدون رمز، **بدون هیچ دسترسی شبکه‌ای**. ولی روی XAMPP، Apache یک **سرویس ویندوز** است و PHP را با همان حسابی اجرا می‌کند که Apache با آن بالا آمده — و پیش‌فرض XAMPP یعنی **`LocalSystem`**.

`LocalSystem` روی شبکه با نام `ماشین$` شناخته می‌شود و **هیچ دسترسی ادمینی روی کلاینت‌ها ندارد** — نه به `C$`، نه به WMI.

**نتیجهٔ عملی:** وقتی سامانه از داخل مرورگر با Apache استخراج را صدا می‌زند، آن کد با حساب `LocalSystem` اجرا می‌شود، نه با حساب شما. مهم نیست که در پنل با ادمین وارد شده‌اید — این دو تا هیچ ربطی به هم ندارند.

همین ریشهٔ `Access is denied` است. این را بخش **۰.۶** ابزار حالا مستقیم نشان می‌دهد.

---

## گام ۱ — کجا اجرا کنم؟

روی **همان سرور XAMPP**. `Win + R` → `cmd` → `Enter`.

```cmd
cd /d C:\xampp\htdocs\ticket
```

مسیر را با پوشهٔ واقعی خودتان عوض کنید. اگر نمی‌دانید کجاست، در XAMPP Control Panel روی Apache → `Config` → `Apache (httpd.conf)` و مقدار `DocumentRoot` را ببینید.

برای اطمینان — باید `index.php` را ببینید:

```cmd
dir index.php
```

---

## گام ۲ — اجرای ساده (بدون رمز). **از این شروع کنید**

```cmd
C:\xampp\php\php.exe tools\diag_extract.php BAZRESI-PC
```

`BAZRESI-PC` همان نامی است که در پیام خطا آمد.

**چرا مسیر کامل، نه `php`؟** چون XAMPP پیش‌فرض PHP را به `PATH` ویندوز اضافه نمی‌کند. اگر `php` را تایپ کنید، معمولاً `'php' is not recognized` می‌گیرید. `C:\xampp\php\php.exe` همیشه هست.

**بدون هیچ رمزی** اینها را می‌گیرید: عضویت دامنه (بخش ۰.۵)، حساب سرویس Apache (بخش ۰.۶)، DNS، پورت‌های ۱۳۵/۴۴۵/۵۹۸۵ و پیام دقیق WMI.

---

## گام ۳ — اجرای کامل، با حساب ادمین

```cmd
C:\xampp\php\php.exe tools\diag_extract.php BAZRESI-PC CORP\scanuser
```

رمز را **پنهان** می‌پرسد (چیزی روی صفحه ظاهر نمی‌شود — طبیعی است، تایپ کنید و Enter).

در `cmd` **یک** بک‌اسلش بزنید، نه دو تا.

> **اگر رمز ندارید یا نمی‌خواهید وارد کنید، گام ۲ کامل کافی است.** بخش ۴ (بازکردن `C$`) رد می‌شود و بقیه همین را می‌گوید.

---

## گام ۴ — ذخیره و فرستادن

```cmd
C:\xampp\php\php.exe tools\diag_extract.php BAZRESI-PC CORP\scanuser > diag.txt 2>&1
```

فایل `diag.txt` را بفرستید. **رمز در آن نیست** — ابزار هیچ‌جا رمز را چاپ نمی‌کند، و رمز را از خط فرمان هم رد نمی‌کند (از محیط فرآیند می‌رود، که در Task Manager دیده نمی‌شود).

## خروجی را چطور بخوانم؟

### بخش ۰.۵ — عضویت دامنه

```
۰.۵) عضویت سرور در دامنه (تعیین‌کننده‌ترین عامل)
  ✓ عضو دامنه                  CORP
```
→ خوب است، ادامه دارد.

```
  ✗ عضو دامنه                  WORKGROUP
```
→ **تمام.** ویندوز توکن حساب محلی را در اتصال شبکه‌ای فیلتر می‌کند. هیچ ابزاری — نه این، نه TNI، نه ادمین‌یار — از این سرور نمی‌تواند کلاینت‌ها را از راه دور بخواند. مسیر درست: `client-agent` (پایین صفحه).

### بخش ۰.۶ — حساب Apache (فقط روی XAMPP دیده می‌شود)

```
۰.۶) هویت اجرای PHP (تفاوت XAMPP و IIS)
  ✓ حساب کاربری      ADMIN
  ✓ SAPI                       cli
  ✓ حساب سرویس Apache          LocalSystem
      ⚠ Apache با LocalSystem اجرا می‌شود (پیش‌فرض XAMPP).
```

اگر این هشدار را دیدید، ریشه را پیدا کرده‌اید. سه راه دارید:

| راه | کار | هزینه |
|---|---|---|
| **الف — حساب سرویس Apache را عوض کنید** | سرویس Apache را با یک حساب دامنه‌ای که روی کلاینت‌ها ادمین محلی است اجرا کنید | یک بار، ولی از این به بعد همهٔ درخواست‌های Apache با آن حساب به شبکه می‌روند |
| **ب — `client-agent`** | اسکریپت روی خود کلاینت‌ها اجرا می‌شود و نتیجه را با توکن می‌فرستد | هیچ مجوز از راه دوری لازم نیست؛ برای ۱۵۰ کلاینت قابل‌اعتمادترین |
| **ج — LocalAccountTokenFilterPolicy** | روی **هر کلاینت** با GPO: `LocalAccountTokenFilterPolicy=1` | امنیت را کم می‌کند؛ توصیه نمی‌شود |

**راه ب پاسخ همان چیزی است که خودِ ادمین‌یار «روش پیشنهادی» می‌نامد** — اجرای محلی روی هر کلاینت، نه اسکن از راه دور.

### بخش ۲ — پورت‌ها

| نتیجه | معنا |
|---|---|
| `۴۴۵ ✓` | مسیر SMB باز است |
| `۴۴۵ ✗` | فایروال مقصد یا سرویس File and Printer Sharing |
| `۱۳۵ ✓` و `۵۹۸۵ ✗` | DCOM باز است، WinRM نه |

### بخش ۳ — پیام دقیق WMI

- `Access is denied` → مجوز/توکن. **فایروال مقصر نیست.** با حساب Apache بالا بخوانید.
- `RPC server is unavailable` → بسته رسیده نشده. فایروال یا سرویس WMI.

## راه جایگزین: دکمهٔ batch

اگر نمی‌خواهید مسیر php را تایپ کنید:

```cmd
tools\RUN-DIAG-EXTRACT.bat BAZRESI-PC
```

خودش `C:\xampp\php\php.exe` را پیدا می‌کند.

## مسیر `client-agent` — وقتی اسکن از راه دور درست نیست

این مسیر به هیچ مجوز از راه دور، هیچ عضویت دامنه، و هیچ تنظیم Apache نیاز ندارد:

**روی هر کلاینت** (یا با GPO روی همهٔ ۱۵۰ تا):

```powershell
powershell -ExecutionPolicy Bypass -File Collect-Inventory.ps1 `
  -Endpoint "http://IP-سرور/htdocs/ticket/api/inventory.php" `
  -AllowInsecureHttp
```

> از `-AllowInsecureHttp` فقط در شبکهٔ داخلی استفاده کنید. با HTTPS این سوییچ لازم نیست.

اسکریپت اطلاعات را روی **خود کلاینت** می‌خواند و با توکن می‌فرستد — همان الگویی که AdminYar پیشنهاد می‌کند.

## اگر خطا گرفتید

| پیام | یعنی | کار |
|---|---|---|
| `'php' is not recognized` | XAMPP در PATH نیست | مسیر کامل: `C:\xampp\php\php.exe` |
| `Could not open input file` | در پوشهٔ اشتباه هستید | `cd /d C:\xampp\htdocs\ticket` |
| `Access denied` | cmd معمولی است | Run as administrator |
| `PDOException` / `Connection refused` | MySQL وصل نیست | XAMPP Control Panel → MySQL → Start |
| `رمز خالی بود` | رمز را خالی رد کردید | بدون نام کاربری اجرا کنید (گام ۲) |
| `این ابزار فقط از خط فرمان اجرا می‌شود` | از مرورگر بازش کردید | باید در `cmd` اجرا شود |
