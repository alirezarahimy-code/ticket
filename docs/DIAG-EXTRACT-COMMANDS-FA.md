# دستور اجرای دقیق — تشخیص مشکل استخراج شناسنامه

**نسخه:** ۱.۶۳.۱-r17 · **فایل:** `tools/diag_extract.php`

این ابزار هیچ چیزی را تغییر نمی‌دهد. فقط می‌خواند و می‌گوید کدام شرط شکسته است.

---

## قبل از شروع: این را کجا اجرا کنم؟

روی **همان سروری که سامانه روی آن نصب است** — نه روی کلاینت، نه روی رایانهٔ خودتان.

| اگر سامانه با… | اجرا در |
|---|---|
| IIS | `cmd` روی سرور، با **Run as administrator** |
| XAMPP / WAMP | `cmd` روی همان سیستم |
| PHP CLI | همان `cmd` |

**علت:** ابزار باید با همان حساب و همان تنظیماتی اجرا شود که خودِ سامانه دارد. اگر روی رایانهٔ دیگری اجرا شود، عضویت دامنهٔ آن سیستم سنجیده می‌شود، نه سرور سامانه — و نتیجه بی‌معنی است.

---

## گام ۱ — باز کردن cmd در پوشهٔ سامانه

`Win + R` → تایپ `cmd` → `Enter` → بعد:

```cmd
cd /d C:\inetpub\wwwroot\ticket
```

مسیر را با مسیر واقعی نصب خودتان عوض کنید. اگر نمی‌دانید کجاست: در IIS Manager روی سایت راست‌کلیک → `Manage Website` → `Advanced Settings` → مقدار `Physical Path`.

برای اطمینان این را بزنید؛ باید `index.php` را ببینید:

```cmd
dir index.php
```

---

## گام ۲ — اجرای ساده (بدون رمز)

**همیشه با این شروع کنید.** لازم نیست رمزی وارد کنید و پاسخ بیشتر سؤال‌ها را می‌دهد:

```cmd
php tools\diag_extract.php BAZRESI-PC
```

یا با فایل کمکی که `php` را خودش پیدا می‌کند (اگر پیام «php شناخته نشد» گرفتید):

```cmd
tools\RUN-DIAG-EXTRACT.bat BAZRESI-PC
```

> `BAZRESI-PC` را با نام واقعی همان کامپیوتری عوض کنید که استخراجش خطا می‌دهد — همان نامی که در پیام خطا آمده بود.

---

## گام ۳ — اجرای کامل (با حساب ادمین، برای آزمون SMB)

بعد از این‌که گام ۲ را دیدید، برای کامل‌شدن تشخیص:

```cmd
php tools\diag_extract.php BAZRESI-PC CORP\scanuser
```

ابزار رمز را **پنهان** می‌پرسد (کاراکترها نمایش داده نمی‌شوند). رمز روی خط فرمان نمی‌آید و جایی ذخیره نمی‌شود.

**سه نکتهٔ مهم:**

1. `CORP` نام NetBIOS دامنه است — همان چیزی که در تنظیمات ← اسکن دامنه وارد کرده‌اید. اگر نمی‌دانید، فقط نام کاربر را بنویسید: `php tools\diag_extract.php BAZRESI-PC scanuser`
2. در `cmd` یک بار `\` بنویسید، نه دو بار. فقط داخل PowerShell نیاز به `\\` یا نقل‌قول است.
3. اگر رمز ندارید یا نمی‌خواهید وارد کنید، گام ۲ کافی است و همهٔ پورت‌ها و عضویت دامنه را می‌سنجد؛ فقط بخش ۴ (بازکردن `C$`) رد می‌شود.

### اگر cmd می‌گوید `php` شناخته نشد

PHP در `PATH` نیست (روی IIS معمول است):

```cmd
"C:\Program Files\PHP\v8.2\php.exe" tools\diag_extract.php BAZRESI-PC
```

نسخهٔ `v8.2` را با نسخهٔ خودتان عوض کنید. برای پیدا کردنش:

```cmd
where /r "C:\Program Files" php.exe
```

یا ساده‌تر: `tools\RUN-DIAG-EXTRACT.bat BAZRESI-PC` — این فایل خودش همهٔ مسیرهای رایج را می‌گردد.

---

## گام ۴ — فرستادن خروجی

خروجی را کپی کنید یا مستقیم در فایل ذخیره کنید:

```cmd
php tools\diag_extract.php BAZRESI-PC CORP\scanuser > diag.txt 2>&1
```

فایل `diag.txt` ساخته می‌شود؛ همان را بفرستید. **رمز در آن نیست** — ابزار هیچ‌جا رمز را چاپ نمی‌کند.

---

## خروجی چه معنایی دارد؟

اولین چیزی که باید ببینید، **بخش ۰.۵** است:

```
۰.۵) عضویت سرور در دامنه (تعیین‌کننده‌ترین عامل)
  ✓ عضو دامنه                  CORP
```
→ خوب است. مسیر SMB/WinRM می‌تواند کار کند.

```
  ✗ عضو دامنه                  WORKGROUP
```
→ **همین ریشهٔ «Access is denied» است.** ویندوز توکن حساب محلی را در اتصال شبکه‌ای فیلتر می‌کند و هیچ کدی از سمت سامانه دورش نمی‌زند. در این حالت `client-agent` مسیر درست است، نه اسکن از راه دور.

بعد **بخش ۲** (پورت‌ها):

| نتیجه | معنا |
|---|---|
| `445 ✓` | مسیر SMB باز است — روش دوم r17 می‌تواند کار کند |
| `445 ✗` | فایروال مقصد یا سرویس File and Printer Sharing |
| `135 ✓` و `5985 ✗` | DCOM باز است، WinRM نه |

و **بخش ۳** — پیام دقیق WMI:

- `Access is denied` → مجوز/توکن. فایروال مقصر نیست.
- `RPC server is unavailable` → بسته نرسیده. فایروال یا سرویس WMI.

## اگر خطا گرفتید

| پیام | یعنی | کار |
|---|---|---|
| `این ابزار فقط از خط فرمان اجرا می‌شود` | از مرورگر بازش کردید | باید در `cmd` اجرا شود، نه در مرورگر |
| `php` شناخته نشد | PHP در PATH نیست | گام ۳، بخش «اگر cmd می‌گوید php شناخته نشد» |
| `Could not open input file` | در پوشهٔ اشتباه هستید | `cd /d` به مسیر نصب (گام ۱) |
| `Access denied` هنگام اجرا | cmd معمولی است، نه Administrator | `cmd` را با Run as administrator باز کنید |
| `Connection refused` / `PDOException` | اتصال دیتابیس برقرار نشد | سرویس MySQL/MariaDB و `config.php` را بررسی کنید |
| `رمز خالی بود` | رمز را خالی رد کردید | همان دستور را بدون نام کاربری اجرا کنید (گام ۲) |

## در PowerShell (اگر ترجیح می‌دهید)

```powershell
cd "C:\inetpub\wwwroot\ticket"
php tools\diag_extract.php BAZRESI-PC
```

برای نام کاربر در PowerShell، بک‌اسلش را با نقل‌قول بگذارید:

```powershell
php tools\diag_extract.php BAZRESI-PC "CORP\scanuser"
```

---

## اگر PHP روی سرور نیست (سامانه روی Linux است)

ابزار اجرا می‌شود ولی بخش‌های ویندوزی را رد می‌کند و همین را می‌گوید. در آن حالت:

- مسیر WMI/SMB از یک میزبان Linux معنا ندارد؛
- برای ۱۵۰ کلاینت از `client-agent/Collect-Inventory.ps1` روی خود کلاینت‌ها استفاده کنید (بخش ۷.۸ راهنمای نصب).
