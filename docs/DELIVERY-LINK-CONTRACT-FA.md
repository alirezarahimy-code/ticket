# قرارداد ثابت تحویل لینک — فقط لینک متنی مستقیم از GitHub

> تاریخ: ۲۰۲۶-۱۱-۱۹ · منشأ: دستور صریح کاربر: «یک قرار داد با تو. از این به بعد تمام نسخهها یا هر فایلی که میخوای بهم بدی الزاماً فقط با همین روش بهم لینک رو برسون».
> این قاعده **غیرقابل مذاکره** است و برای هر تحویل بعدی، بدون آنکه دوباره پرسیده شود، اجرا میشود.

## دامنه

همهٔ نسخهها (بستههای بهروزرسانی، ZIPها، `manifest.json`، `CHANGE-REPORT-FA.md`) و **هر فایل دیگری** که قرار است به کاربر تحویل داده شود: XLSX، HTML، PDF، MD، TXT، تصویر، لاگ، گزارش، فونت، asset و … . فرقی نمیکند فایل تازه ساخته شده باشد یا از قبل موجود باشد.

## روش یگانهٔ تحویل

۱. فایل حتماً در شاخهٔ **فعال همان جلسه** `commit` و `git push origin <شاخهٔفعلی>` شود. اگر شاخه `behind` بود، پیش از push یک `git pull --no-rebase origin <شاخه>` (ادغام معمولی). **هرگز** `push --force`، `reset --hard`، تغییر شاخه یا push به شاخهای دیگر.
۲. لینک **حدسی نوشته نشود**: دقیقاً `download_url` همان فایل از API گیتهاب گرفته شود و `size` و git‑blob‑`sha` با فایل لوکال مقایسه شوند:

   ```bash
   gh api "repos/<owner>/<repo>/contents/<path>?ref=<شاخه>" --jq '"\(.download_url)\n\(.size)\n\(.sha)"'
   sha256sum <path>
   ```

۳. لینک به کاربر **فقط بهصورت URL خامِ متنی** داده شود: داخل بلوک کد `text`، بدون Markdown `[متن](url)`، بدون دکمه/کارت/آیکون و بدون متن لینکدار. الگو:

   ```text
   https://raw.githubusercontent.com/alirezarahimy-code/ticket/<شاخه>/downloads/<فایل>.zip
   ```

   جایگزینِ **همان روش** (فقط اگر `raw.githubusercontent.com` در شبکهٔ کاربر بسته بود) نسخهٔ همان فایل روی دامنهٔ `github.com` است:

   ```text
   https://github.com/alirezarahimy-code/ticket/raw/refs/heads/<شاخه>/downloads/<فایل>.zip
   ```

۴. برای هر بسته/فایل باینری، فایل `.sha256` کنارش ساخته و push شود و لینک متنی جداگانهاش داده شود؛ SHA‑256 کامل هم در متن پاسخ نوشته شود.
۵. پیش از اعلام تحویل، از راه دور تأیید شود: `gh api` فایل را ببیند، `git ls-remote` سرِ شاخهٔ درست باشد، و محتوای لوکال/ریموت بایتبهبایت برابر باشد.

## ممنوع بهعنوان روش رساندن لینک

- لینک پیشنمایش زنده `https://{port}-{sandbox}.e2b.app/…` — شکست خورد؛ لاگ سرور هیچ درخواستی از مرورگر ثبت نکرد.
- لینک نسبی سرور محلی `href="/downloads/…"` داخل ویور — به اوریجین ویور میرود و ۴۰۴ میدهد.
- `present_file` بهعنوان مسیر تحویل فایل.
- `data:…;base64,` جاسازیشده داخل HTML بهعنوان «لینک تحویل» — آن فقط یک fallback داخل همان پیشنمایش است، روش تحویل نیست.
- لینک Markdown، لینک صفحهٔ `downloads/index.html`، لینک Release، یا هر میانجی دیگری بهجای URL مستقیم خود فایل.
- حدس زدن URL، یا دادن لینک پیش از push و تأیید از راه دور.

## نسبت با قواعد پیشین

`docs/DOWNLOAD-PUBLISHING-POLICY-FA.md` و بند ۱ `docs/HANDOFF-FA.md` همچنان لازمالاجرااند؛ این سند **جایگزین الزامات انتشار نمیشود**، فقط تعیین میکند که در **پاسخ نهایی به کاربر** کدام لینک و با چه قالبی رسانده شود. یعنی انتشار (صفحهٔ دانلود، Release، checksum) طبق قواعد قبلی انجام میشود، ولی پاسخ فقط لینک متنی مستقیم GitHub میگیرد.

## استثنای یگانه

فقط وقتی کاربر در همان پیام صریحاً روش دیگری بخواهد. در غیر این صورت، حتی برای فایلهای کوچک و حتی در پاسخهای کوتاه، همین روش اجرا میشود.
