# راهنمای عملیات Logging — 1.62.76

## ارتقا

1. Base Version را دقیقاً `1.62.75` تأیید کنید.
2. Backup فایل و دیتابیس تهیه و Restore را روی Clone آزمایش کنید.
3. Update نسخه 1.62.76 را از طریق Updater داخلی روی Staging اعمال کنید.
4. این نسخه Migration جدید ندارد.
5. پس از آزمون پذیرش، پایلوت را با دامنه کاربران و عملیات محدود آغاز کنید.

## کنترل‌های عملیاتی جدید

- موفقیت Audit در تراکنش فعال، هنگام Circuit Open به Spool مستقل منتقل نمی‌شود؛ عملیات حساس fail-closed می‌شود.
- وضعیت Spool و Dead Letter را پس از هر اختلال DB بررسی کنید.
- در لاگ فعالیت، فیلتر Module و Category Audit را برای بررسی عملیات بین‌ماژولی به‌کار ببرید.
- در Ticket، تاریخچه را با `event_q` جست‌وجو و با صفحه‌بندی مرور کنید.
- جزئیات داخلی فقط برای نقش‌های مجاز نمایش داده می‌شود.

## حدود استفاده

نسخه برای پایلوت کنترل‌شده طراحی شده است. تا پذیرش MySQL/Windows/Staging مقصد و سناریوهای Restore/Rollback، تنها مرجع قطعی حسابرسی عملیات حساس محسوب نمی‌شود.
