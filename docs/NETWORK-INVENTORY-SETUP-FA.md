# راهنمای اسکن شبکه‌ای رایانه‌های Windows از سامانهٔ Ticket

**دامنه:** جمع‌آوری راه‌دور از رایانه‌های دامنه با یک حساب مجاز؛ نه استخراج سخت‌افزار مرورگر

## نتیجهٔ بررسی منابع رسمی

- فروشندهٔ Total Network Inventory (TNI) در صفحهٔ محصول می‌گوید برای اسکن شبکه عامل دائمی روی مقصد لازم نیست و اسکن از یک رایانه با رمز مدیر انجام می‌شود. سند فنی خودش توضیح می‌دهد روش اصلی Windows، بارگذاری عامل موقت روی `ADMIN$` و اجرای سرویس آن است؛ روش دیگر WMI مستقیم از طریق RPC است. بنابراین «فقط رمز» خلاصهٔ تجربهٔ کاربری است، نه حذف نیازهای شبکه و فایروال.
- راهنمای TNI صریحاً می‌گوید حساب باید روی مقصد مجوز مدیر محلی یا Domain Admin داشته باشد. برای روش‌های خودش نیز دسترسی SMB/ADMIN$ و سرویس‌ها یا WMI/RPC و پورت‌های مربوط لازم است.
- Microsoft هم برای WMI راه‌دور، وجود دسترسی روی مقصد و پیکربندی درست Firewall/DCOM/UAC را پیش‌نیاز می‌داند. PowerShell می‌تواند WMI را با نام کامپیوتر و اعتبارنامهٔ جایگزین بخواند.
- PowerShell Remoting با WinRM روش دیگری است: دسترسی پیش‌فرض به endpointها برای Administrators است؛ پورت معمول HTTP برابر TCP 5985 و HTTPS برابر TCP 5986 است. برنامهٔ Ticket در حال حاضر برای مسیر WSMan از پیش‌فرض TCP 5985 استفاده می‌کند؛ TLS مرورگر تا پنل نیز جداگانه باید HTTPS باشد.

## معماری Ticket و تفاوت استخراج محلی/شبکه‌ای

- برای اسکن شبکه‌ای، برنامهٔ PHP و PowerShell فقط روی **یک میزبان مرکزی Windows** اجرا می‌شوند؛ PHP روی ۱۵۰ کلاینت لازم نیست.
- اسکریپت `tools/collect_server_inventory.ps1` با CIM/WMI روی میزبان مرکزی اجرا می‌شود و برای هدف دور از DCOM یا WSMan استفاده می‌کند. اسکن کامل دامنه، تمام اشیای کامپیوتری بازگشتی از جست‌وجوی صفحه‌بندی‌شدهٔ AD را صف می‌کند (بدون سقف ۹۰۰تایی انتخاب گروهی). این پیاده‌سازی عامل TNI را کپی/نصب نمی‌کند؛ از روش‌های مدیریت خود Windows استفاده می‌کند.
- برای مقصدهای موفق، علاوه بر مشخصات اصلی، جزئیات رایج CPU/BIOS/SMBIOS، ماژول و اسلات RAM، دیسک و فضای منطقی، شبکه، مانیتور و PnP، درایورهای امضاشده، نرم‌افزار نصب‌شده، HotFixهای گزارش‌شدهٔ WMI، آنتی‌ویروس/فایروال‌های گزارش‌شده، سرویس‌ها، پردازه‌ها (بدون command line)، startup، shareها، حساب‌ها و شاخص‌های سلامت ذخیره‌سازیِ در دسترس جمع می‌شود. داده‌های تکمیلی زیر `hardware_json.extended_inventory` قابل مشاهده است.
- پس از هر اسکن موفق، فیلدهای خودکار شناسنامه از دادهٔ تازه به‌روزرسانی می‌شوند؛ فیلدهای سازمانی و دستی (مانند پلاک، کاربر مسئول، شماره پرسنلی و پلمپ) دست‌نخورده می‌مانند. دسترسی واقعی اینترنت از روی وجود Gateway قابل اثبات نیست و آن فیلد دستی باقی می‌ماند.
- «استخراج محلی همین سیستم» فقط میزبان اجرای PHP را می‌خواند. برای رایانه‌های دیگر از «استخراج اطلاعات سیستم‌های انتخاب‌شده» یا صفحهٔ «اسکن دامنه» استفاده کنید.
- می‌توان همان حساب Domain Admin را یک‌بار در فرم هر نوبت وارد کرد؛ نیازی به ساخت ۱۵۰ حساب محلی نیست. حساب باید در عمل روی مقصدها عضو Administrators باشد. اگر GPO عضویت Domain Admins را از Administrators محلی حذف کرده باشد، همان حساب هم مجاز نخواهد بود.
- اعتبارنامهٔ فرم با HTTPS دریافت و فقط رمز‌شده، موقت و وابسته به نشست/نوبت نگهداری می‌شود؛ در جدول تنظیمات یا پایگاه‌داده ذخیرهٔ دائمی نمی‌شود.

## روال پیشنهادی

1. **میزبان پنل:** روی Windows server/PC مرکزی، PHP و PowerShell در دسترس باشند؛ `proc_open` در PHP غیرفعال نباشد و پنل از HTTPS باز شود. این میزبان باید از طریق DNS و شبکه به رایانه‌های مقصد دسترسی داشته باشد.
2. **دادهٔ هدف:** برای یک اسکن سراسری، صفحهٔ «اسکن دامنه» تمام رایانه‌های پیدا‌شده در Active Directory را صف می‌کند؛ کشف LDAP به میزبان کنترلر و Base DN تنظیم‌شده نیاز دارد. استخراج گروهی از صفحهٔ دارایی‌ها برای فهرست‌های دستی/محدود است. حسابی که در فرم اسکن وارد می‌کنید همان یک حساب مجاز روی همهٔ مقصدهاست؛ برای هر PC حساب محلی جدا نسازید.
3. **یک آزمون قبل از گروه:** دقیقاً یک رایانهٔ روشن و قابل‌دسترسی را انتخاب کنید، حساب را با قالب `DOMAIN\\username` وارد و «آزمون حساب روی یک سیستم» را بزنید. این آزمون PowerShell/WMI را اجرا می‌کند اما چیزی در شناسنامه ذخیره نمی‌کند. اگر موفق شد، همان حساب را برای استخراج گروهی وارد کنید.
4. **پروتکل شبکه:** حالت پیش‌فرض DCOM را امتحان می‌کند و سپس WSMan. اگر شبکه WinRM را فراهم کرده، «اول WinRM» را انتخاب کنید. پینگ ICMP فقط یک نشانه است؛ Ticket اکنون پورت 5985 را نیز برای یافتن مقصدهای WinRM می‌آزماید.
5. **Firewall/GPO:** برای DCOM، روی مقصدها WMI-In/Remote Administration و دسترسی RPC لازم است: TCP 135 به‌علاوهٔ پورت‌های پویا RPC. برای WinRM، سرویس/Listener و قاعدهٔ Windows Remote Management باید روی **مقصدها** فعال باشد و TCP 5985 از میزبان پنل تا مقصد باز باشد. قاعده‌ها را ترجیحاً در GPO دامنه و به IP میزبان اسکن محدود کنید؛ فایروال یا UAC را به‌طور کلی خاموش نکنید.
6. **استخراج همهٔ دامنه:** در صفحهٔ «اسکن دامنه» «شروع اسکن دامنه» را بزنید. هر کامپیوتر AD وارد صف می‌شود؛ پردازش دسته‌ای ادامه می‌یابد و موفق، آفلاین و خطادار برای هر میزبان جدا ثبت می‌شود. برای رایانه‌های روشن ولی ناموفق، راه‌حل علت خطا را اجرا و «تلاش دوباره» را بزنید. انتخاب دستی از صفحهٔ دارایی‌ها سقف ۹۰۰ سیستم در هر نوبت دارد؛ این سقف برای صف کامل AD نیست.
7. **بیرون شبکه:** وقتی میزبان پنل به شبکه/VPN مقصد دسترسی ندارد، اسکن راه‌دور انجام نمی‌شود. در این وضعیت استخراج محلی فقط همان میزبان PHP را می‌خواند؛ برای کلاینت‌های خارج از شبکه باید عامل/اسکریپت محلی با ارسال نتیجه به سامانه طراحی شود.

## محدودهٔ امنیتی و امکانات

- عضویت Domain Admin معمولاً روی رایانه‌های دامنه دسترسی ادمین می‌دهد، اما این نتیجه تابع GPO و سیاست‌های سازمان است؛ آزمون تک‌سیستم آن را در محیط واقعی روشن می‌کند.
- این گسترش، جمع‌آوری را به دسته‌های بیشتری از TNI نزدیک می‌کند، اما **برابری کامل یا «همهٔ زیر و بم» TNI نیست**: WMI/CIM همهٔ update history، inventory نرم‌افزار per-user، همهٔ جزئیات امنیتی/پایگاه‌داده و تمام device telemetry را تضمین نمی‌کند؛ SPD خام RAM و SMART کامل فقط وقتی درایور/provider ویندوز مقصد آن را ارائه کند در دسترس است. Ticket عامل موقت و driver اختصاصی TNI را نصب نمی‌کند. مقادیر متغیرهای محیطی و command line پردازه‌ها عمداً ذخیره نمی‌شوند تا احتمال جمع‌آوری رمز/توکن کم شود.
- «همهٔ کامپیوترهای دامنه» یعنی تمام اشیای کامپیوتری که AD برمی‌گرداند؛ فقط میزبان‌های روشن و قابل‌دسترسی که دسترسی WMI/CIM موفق دارند جزئیات زنده خواهند داشت. سیستم خاموش/خارج شبکه در فهرست AD می‌ماند و بعداً باید دوباره اسکن شود.
- اسکن شبکه‌ای روی سرویس‌های Windows، سیاست فایروال و سرعت/بار شبکه وابسته است. ابتدا یک مقصد، سپس گروه کوچک و بعد همهٔ دستگاه‌ها را آزمایش کنید.
