# ماتریس پوشش آزمون سامانه (محیط مصنوعی)

**آخرین اجرای مرجع:** GitHub Actions run `39887223768`، روی branch کاری `arena/8edbdf95-ticket`؛ همهٔ داده‌ها و حساب‌ها synthetic و DB دورریختنی بودند. هیچ production یا staging استفاده نشد.

این ماتریس محدودهٔ آزمون واقعی را از قسمت‌هایی که هنوز فقط جزئی/آفلاین هستند جدا می‌کند. وضعیت «پوشش منتخب» به معنی آزمودن همهٔ رفتارهای همان ماژول نیست.

## اعداد اجرای مرجع

- Route/API smoke: **۱۸۹ بررسی، ۱۸۹ موفق، صفر شکست**؛ ۳۷ صفحه، ۷۱ GET API، ۶۰ بررسی نقش.
- ۳۷ پاسخ HTTP خطادار ثبت شد؛ ۲۸ مورد رد دسترسی 401/403 موردانتظار بودند و بقیه شامل ورودی نامعتبر، CSRF نامعتبر، مسیر cron غیرقابل‌دسترسی یا backup ناموجود بودند. **خطای HTTP غیرمنتظره: صفر**.
- PHP runtime error log: **۰**؛ DB/SQL error log: **۰**.
- آزمون‌های Python: **۱۳۸ passed، ۱۸ subtests passed**؛ آزمون‌های JS، PHP offline و DB smoke هم در همان CI موفق بودند.
- آزمون route resilience: ۲۵۰ کاربر مجازی، ۳۲ worker PHP، ۶۶ مسیرِ دارای ترافیک، ۳۰۰۰ درخواست خواندنی + ۵۰۰ درخواست ورود؛ خطای درخواست، worker، PHP یا DB گزارش نشد.
- آزمون نوشتنی: ۲۵۰ نشست و ۱۸۷۰ عملیات منطقی؛ نرخ ثبت‌شده ۷۲٫۵۳ عملیات/ثانیه؛ خطای عملیات و هشدار PHP صفر.
- گزارش جزئی همان اجرا در `benchmark-results/full-system-route-smoke.md`، `benchmark-results/system-resilience.md` و `benchmark-results/benchmark-operations.md` است. جزئیات cron در `benchmark-results/full-system-cron-tests.log` ثبت شده است.

## کندی مشاهده‌شده — علت هنوز تشخیص داده نشده

در آزمون route resilience همین اجرای CI، latency خواندن‌ها p50 حدود **۱٫۶۰ ثانیه**، p95 حدود **۲٫۸۴ ثانیه** و بیشینه حدود **۴٫۱۰ ثانیه** بود؛ p95 ورود حدود **۵٫۵۷ ثانیه**. در آزمون نوشتنی، p95 ورود POST حدود **۵٫۸۲ ثانیه** و ایجاد تیکت حدود **۴٫۴۹ ثانیه** بود. این‌ها اندازه‌گیری‌های ۲۵۰ کاربر مجازی روی runner موقت GitHub هستند، نه اندازه‌گیری production. علت ریشه‌ای با profiler یا trace سطح query تعیین نشده و نباید از این اعداد به‌تنهایی علت خاصی نتیجه گرفت.

## موارد باقی‌مانده

- آزمودن تمام ترکیب‌های نقش، صفحه، API، verb، CSRF و transition؛ اکنون فقط نقاط مرزی منتخب پوشش دارند.
- اجرای تمام handlerهای POST در غذا، سازمان، کاربران، تنظیمات، ticket attachments/imports و ماژول‌های مدیریتی با lifecycle مستقل و rollback/cleanup.
- رفتار واقعی LDAP/AD، PowerShell/CIM/WMI، Access/ODBC، filesystem عملیاتی، سرویس‌های بیرونی، printer spooler و سخت‌افزار.
- ساخت backup و restore واقعی روی یک DB جداگانه، مهاجرت زنجیره‌ای از نسخه‌های قدیمی و آزمون بازیابی فایل‌ها.
- مرورگر واقعی برای UI، چاپ/preview واقعی، دسترس‌پذیری و تعامل‌های end-to-end.
- profiling کندی‌های مشاهده‌شده، شامل تفکیک زمان برنامه، lock/session، query، DB و اشباع منابع؛ هنوز هیچ علت یا اصلاح performance تأیید نشده است.

هیچ موردی از موارد باقی‌مانده نباید به‌عنوان آزموده‌شده تلقی شود تا اجرای جداگانه و گزارش شواهد آن انجام شود.
