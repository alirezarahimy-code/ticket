# راهنمای گام‌به‌گام نصب ۱.۶۳.۱

**برای:** سامانه‌ای که هم‌اکنون **۱.۶۳** روی آن نصب است و این سه هشدار را نشان می‌دهد:

- پوشهٔ `storage/food_ticket_spool` در دسترس نیست
- مهاجرت‌های `001-local-accounts.sql`، `002-traffic-notices.sql`، `015-asset-identity-hotfix.sql` اجرا نشده
- دیده‌بانی خودکار سلامت به‌روز نیست (کرون)

هیچ‌کدام از این‌ها را **دستی** درست نکنید. بستهٔ ۱.۶۳.۱ دو مورد اول را خودش درمان می‌کند.

## پیش از شروع — ۵ دقیقه

### ۱) ببینید نسخهٔ فعلی‌تان چیست

فایل `VERSION` را در پوشهٔ نصب باز کنید.

| مقدار داخل فایل | یعنی | کار شما |
|---|---|---|
| `1.63` | نسخهٔ r16 نصب است | ✅ همین راهنما |
| `1.63.1` | قبلاً نصب کرده‌اید | 🎉 برو به بخش «بعد از نصب» |
| `1.62.x` یا کمتر | نسخهٔ قدیمی‌تر | ⚠️ اول ۱.۶۳ را نصب کنید، بعد این را |

### ۲) پشتیبان بگیرید

```
۱. پوشهٔ نصب را کامل کپی کنید (مثلاً ticket-backup-14050825)
۲. از پایگاه داده یک dump بگیرید:
       mysqldump -u root -p persian_ticketing > backup-14050825.sql
```

> اگر این کار را نکنید و وسط کار چیزی خراب شود، راه برگشتی ندارید.

### ۳) فایل را دانلود کنید

**[⬇ دانلود بستهٔ میانی ۱.۶۳ ← ۱.۶۳.۱](https://github.com/alirezarahimy-code/ticket/raw/publish-1.63.1/downloads/ticket-update-1.63-to-1.63.1-r14-org-profile-20261115.zip)**

این راهنما **داخل خود بسته** هم منتشر می‌شود، پس حجم و هشِ دقیقِ همین زیپ
را نمی‌تواند درست حمل کند (هر بار که راهنما تغییر کند، زیپ هم عوض می‌شود).

حجم و SHA-256 را از صفحهٔ دانلود بردارید:

- [`downloads/README-FA-downloads.md`](../downloads/README-FA-downloads.md)
- [`downloads/RELEASE-ASSETS-1.63.1.txt`](../downloads/RELEASE-ASSETS-1.63.1.txt)

**هش را بررسی کنید** (اختیاری ولی توصیه‌شده). در PowerShell:

```powershell
Get-FileHash .\ticket-update-1.63-to-1.63.1-r13-cancel-fix-*.zip -Algorithm SHA256
```

خروجی را با مقدار `SHA-256` همان دو فایل بالا مقایسه کنید.

## نصب — ۲ دقیقه

### گام ۱) Worker را موقتاً متوقف کنید

Worker چاپ غذا یک **وظیفهٔ زمان‌بندی‌شده** است (نه سرویس ویندوز)، با نام `FoodTicket-Worker`:

```cmd
schtasks /End /TN "FoodTicket-Worker"
```

فرآیندهای باقی‌ماندهٔ PHP که همان Worker باشند:

```cmd
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='php.exe'\" | Where-Object { $_.CommandLine -like '*food_ticket_worker.php*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }"
```

> ساده‌تر: فایل `restart-food-worker-SERVICE.bat` همین کار را می‌کند (توقف + پاک‌سازی + شروع). می‌توانید از آن استفاده کنید.

**وب‌سرور (IIS) را لازم نیست متوقف کنید** — کپی فایل‌های PHP در حال اجرا مشکلی ایجاد نمی‌کند.

### گام ۲) فایل زیپ را باز کنید

**روی پوشهٔ نصب خود سامانه** باز کنید. یعنی محتوای پوشهٔ `files/` داخل زیپ باید **بالای** فایل‌های موجود شما برود.

```
پوشهٔ نصب شما:  C:\inetpub\wwwroot\ticket\
داخل زیپ:        files\VERSION
                 files\lib\system-alarms.php
                 files\food-ticket.php
                 ...

بعد از باز کردن باید بشود:
                 C:\inetpub\wwwroot\ticket\VERSION
                 C:\inetpub\wwwroot\ticket\lib\system-alarms.php
                 C:\inetpub\wwwroot\ticket\food-ticket.php
```

> ⚠️ **اشتباه رایج:** اگر پوشهٔ `files` را کامل کپی کنید، مسیرهایتان می‌شود `ticket\files\lib\...` و **هیچ‌چیز کار نمی‌کند**. محتوای `files` را کپی کنید، نه خودِ `files` را.

### گام ۳) بررسی کنید که VERSION عوض شد

فایل `VERSION` را باز کنید. باید بنویسد:

```
1.63.1
```

اگر هنوز `1.63` است، فایل‌ها در جای اشتباهی کپی شده‌اند. برگردید به گام ۲.

### گام ۴) کرون را ثبت کنید ⚠️ مهم

**این گام با نصب بسته حل نمی‌شود** — کرون یک وظیفهٔ ویندوز است، نه یک فایل در پوشهٔ سامانه.

روی این فایل **دوبار کلیک کنید** (یا در CMD با دسترسی Administrator اجرا کنید):

```
cron\register_system_alarm_tasks.bat
```

خروجی موفق چیزی شبیه این است:

```
─── ثبت کرون آژیر سلامت ───
پوشهٔ برنامه: C:\inetpub\wwwroot\ticket
PHP: C:\PHP\php.exe
[۱/۲] ثبت tick هر ۵ دقیقه…
[۲/۲] ثبت پیش‌چک روزانه ۰۸:۰۰…

اجرای فوری یک بار (تا هشدار پاک شود)…
       انجام شد.

─── وضعیت ───
TaskName:      \TicketSystemAlarmTick
Status:        Ready
Next Run Time: 1405/08/25 10:20:00
TaskName:      \TicketSystemAlarmMorning
Status:        Ready
Next Run Time: 1405/08/26 08:00:00

تمام شد. صفحهٔ «سلامت سامانه» را تازه‌سازی کنید؛ هشدار باید رفته باشد.
```

> این اسکریپت در پایان **یک بار خودش کرون را فوراً اجرا می‌کند**، پس هشدار همان لحظه باید برطرف شود — لازم نیست ۵ دقیقه صبر کنید.

اگر پیام `[خطا] php.exe پیدا نشد` دیدید، مسیر PHP را دستی بدهید:

```cmd
set PHP_EXE=C:\مسیر\php.exe
cron\register_system_alarm_tasks.bat
```

### گام ۵) Worker را دوباره روشن کنید

```cmd
schtasks /Run /TN "FoodTicket-Worker"
```

یا به‌سادگی فایل `restart-food-worker-SERVICE.bat` را اجرا کنید.

## بعد از نصب — بررسی

### ۱) صفحهٔ **سلامت سامانه** را باز کنید

دو هشدار از سه هشدار باید **ناپدید** شده باشند:

| هشدار | باید بشود |
|---|---|
| پوشهٔ `food_ticket_spool` نیست | ✅ رفع شد (پوشه خودکار ساخته شد) |
| مهاجرت‌ها اجرا نشده | ✅ رفع شد (ثبت شدند) |
| کرون به‌روز نیست | ✅ رفع شد (اسکریپت در پایان یک بار فوراً اجرایش می‌کند) |

> اگر هنوز کرون هشدار می‌دهد، یعنی `register_system_alarm_tasks.bat` اجرا نشده یا خطا داده. صفحه را تازه‌سازی کنید؛ اگر نرفت، گام ۴ را دوباره اجرا کنید.

### ۲) پوشه‌ها را چشمی چک کنید

```
ticket\storage\food_ticket_spool\    ← باید باشد
ticket\storage\food_ticket_prints\   ← باید باشد
```

### ۳) پاپ‌آپ «تغییرات این نسخه» را ببینید

بعد از ورود به سامانه، یک کارت تغییرات ظاهر می‌شود که می‌گوید ۱.۶۳.۱ نصب شده و چه چیزهایی اصلاح شده. اگر ندیدید، از **راهنما ← تغییرات نسخه‌ها** قابل خواندن است.

## کارهای اختیاری — بعد از نصب

این‌ها **ضروری نیستند**. فقط اگر به موردی نیاز داشتید.

### الف) پر کردن فیش‌های غذا برای روزهای گذشته

اگر شام‌های روزهای گذشته ثبت نشده‌اند:

```
تنظیمات سیستم ← اتصال پایگاه‌ها ← پایین صفحه
کارت «ثبت خودکار فیش روزهای گذشته»

از تاریخ: [مثلاً ۱۴۰۵/۰۷/۰۱]
تا تاریخ: [دیروز]

[پیش‌نمایش]   ← اول این را بزنید، چیزی نمی‌نویسد
[ثبت خودکار]  ← بعد این را
```

یا از خط فرمان:

```cmd
php tools\backfill_food_auto_receipts.php --days 30
php tools\backfill_food_auto_receipts.php --days 30 --apply
```

**چه چیزی ثبت می‌شود؟** شام هر روز + ناهار پنجشنبه/جمعه/تعطیل رسمی. ناهار روزهای کاری دست نمی‌خورد (فیش واقعی از کارت‌خوان دارد).

**چاپ فیزیکی نمی‌شود.** اجرای دوباره ردیف تکراری نمی‌سازد.

### ب) اصلاح تیکت‌های قبلاً بد ارجاع‌شده

تیکت‌هایی که قبلاً اشتباه به ادمین اصلی ارجاع شده‌اند **خودکار جابه‌جا نمی‌شوند**. اول ببینید چه هست:

```cmd
php tools\fix_ticket_assignments.php
```

اگر فهرست منطقی بود، اعمال کنید:

```cmd
php tools\fix_ticket_assignments.php --apply
```

### ج) اجرای آزمون‌ها (برای اطمینان)

```cmd
php tools\test_alarm_selfheal_offline.php
php tools\test_backfill_auto_receipts_offline.php
php tools\test_release_notes_offline.php
```

هر کدام باید در آخر بنویسد `۰ ایراد` یا `FAIL=0`.

## اگر چیزی خراب شد — برگشت

### سامانه بالا نمی‌آید

```cmd
schtasks /End /TN "FoodTicket-Worker"
```

بعد پوشهٔ پشتیبان را برگردانید:

```cmd
rmdir /s /q C:\inetpub\wwwroot\ticket
xcopy /e /i C:\ticket-backup-14050825 C:\inetpub\wwwroot\ticket
```

و پایگاه داده:

```cmd
mysql -u root -p persian_ticketing < backup-14050825.sql
```

### صفحهٔ ۵۰۰ می‌دهد

لاگ خطا را ببینید: `storage\logs\` — آخرین فایل را باز کنید و خط آخرش را بخوانید.

### هشدار «مهاجرت اجرا نشده» هنوز هست

یعنی هشدار واقعی است و مهاجرت‌ها در `schema_updates` نیستند. یک‌بار صفحهٔ سلامت را تازه‌سازی کنید — خوددرمانی هنگام خواندن آلارم اجرا می‌شود. اگر باز هم بود، این را بزنید:

```cmd
php -r "require 'bootstrap.php'; require_once 'lib/system-alarms.php'; print_r(system_alarm_collect());"
```
