# راهنمای نصب نسخهٔ ۱.۶۳.۲ — شناسنامه و TENTER

این بستهٔ تجمعی از نسخهٔ **۱.۶۳** به بعد نصب می‌شود؛ روی ۱.۶۳ و ۱.۶۳.۱ قابل نصب است. اصلاحات شناسنامهٔ رایانه و پاک‌سازی دقیق TENTER را همراه فایل‌های لازم استخراج/تشخیص شبکه دارد. در بسته مهاجرت دیتابیس نیست.

## گزارش مستقل غایبین ناهار

پس از نصب، نمای «غایبین ناهار» از منوی اصلی پنل غذا در دسترس است و دسترسی آن با مجوز موجود `food.reports` کنترل می‌شود. گزارش از API موجود `/api/absent` و بازهٔ شمسی استفاده می‌کند و نمایش یک‌جا/بر اساس معاونت، شمار پرس و افراد یکتا، انتخاب ستون‌ها، مرتب‌سازی، خروجی XLSX و چاپ فهرست دارد. چاپ فهرست، رویداد چاپ فیش یا آمار پایش را تغییر نمی‌دهد؛ برای این نما API و پایگاه‌داده تغییر نکرده‌اند.

## تطبیق غایبین و تعیین تکلیف ماندهٔ غذا

در گزارش تجمیعی، غایبِ موردانتظار از تعداد هویت‌های یکتای سفارش ناهار پس از تطبیق فیش‌های همان روز به دست می‌آید؛ کد ملی اولویت دارد و اگر نباشد کد پرسنلی برای تطبیق استفاده می‌شود. چند ردیف سفارش یا چند فیش برای یک نفر، مهمان‌ها و وعدهٔ شام نباید شمار غایبین را دوبرابر یا کم کنند. ردیف‌های بدون شناسه و فیش‌های بی‌تطبیق در بخش عیب‌یابی گزارش دیده می‌شوند.

هنگام بستن روز، اگر ماندهٔ محاسبه‌شده مثبت باشد، مجموع «پرسل + دورریز + نگه‌داری + سایر» باید دقیقاً برابر مانده باشد؛ کم یا زیاد بودن رد می‌شود. سرور مانده را دوباره محاسبه می‌کند و اگر مقدار نمایش‌داده‌شده در پنل کهنه باشد، ثبت را متوقف می‌کند تا گزارش تازه شود. برای ماندهٔ صفر یا منفی، فقط مجموع صفر پذیرفته است. این اصلاح تغییری در پایگاه‌داده یا migration ندارد.

برای آزمون آفلاین پس از نصب:

```cmd
php tools\test_food_reconciliation_disposition_offline.php
php tools\test_food_aggregate_report_offline.php
```

## قبل از نصب

1. مقدار فایل `VERSION` را در ریشهٔ نصب بررسی کنید. اگر کمتر از `1.63` است، این بسته را مستقیم نصب نکنید؛ ابتدا زنجیرهٔ بسته‌های قبلی را نصب کنید.
2. از فایل‌های برنامه و دیتابیس MySQL/MariaDB نسخهٔ پشتیبان بگیرید. اگر از به‌روزرسان داخلی استفاده می‌کنید، سامانه پیش از اعمال بسته هم پشتیبان می‌سازد.
3. در پنل مدیر اصلی، بخش «به‌روزرسانی و پشتیبان‌گیری» را باز کنید و ZIP نسخهٔ ۱.۶۳.۲ را بارگذاری کنید. پیش‌نیاز بسته `1.63` است؛ روی نسخهٔ `1.63.1` نیز پذیرفته می‌شود.

## نصب دستی (فقط اگر به‌روزرسان داخلی در دسترس نیست)

1. ZIP را باز کنید.
2. **محتویات** پوشهٔ `files/` را به ریشهٔ برنامه کپی و فایل‌های موجود را جایگزین کنید؛ خود پوشهٔ `files/` را کپی نکنید.
3. فایل `VERSION` باید در پایان `1.63.2` باشد.
4. `config.php`، فایل‌های `.env` و داده‌های واقعی `storage/` و `uploads/` را جایگزین یا حذف نکنید.

## بعد از نصب

این بسته هیچ مهاجرت یا تغییر جدولی ندارد. برای بررسی آفلاین از ریشهٔ برنامه با PHP خط فرمان اجرا کنید:

```cmd
php tools\test_source_delete_offline.php
php tools\test_source_time_delete_offline.php
php tools\test_asset_dedupe_offline.php
php tools\test_asset_names_offline.php
php tests\test_asset_inventory_flow_sqlite.php
```

آزمون SQLite به افزونهٔ `pdo_sqlite` نیاز دارد. این آزمون‌ها مسیرهای کد را بررسی می‌کنند؛ اتصال زنده به Access/TENTER، SMB یا WinRM را تأیید نمی‌کنند.

## ردیف‌های قدیمی TENTER

اصلاح نسخهٔ ۱.۶۳.۲ از باقی‌ماندن ردیف‌های بعدی به‌خاطر کسرثانیهٔ Access جلوگیری می‌کند؛ ردیف‌هایی که قبلاً جا مانده‌اند خودکار حذف نمی‌شوند. ابتدا فقط گزارش بگیرید:

```cmd
php tools\repair_source_rows.php
```

گزارش را بررسی کنید، از فایل Access نسخهٔ پشتیبان بگیرید و Worker را در بازهٔ نگهداری متوقف کنید. فقط اگر همهٔ ردیف‌های پیشنهادی درست‌اند، حذف واقعی را با تأیید صریح اجرا کنید:

```cmd
php tools\repair_source_rows.php --apply
```

بدون بررسی گزارش و پشتیبان، `--apply` را اجرا نکنید.

## شناسنامه‌های تکراری

اصلاح هویت و ورود موجودی، شناسنامهٔ تکراری را خودکار ادغام یا حذف نمی‌کند. ابزار ادغام نیز در حالت عادی فقط گزارش می‌دهد:

```cmd
php tools\asset_dedupe.php
```

فقط پس از بررسی گزارش و تهیهٔ پشتیبان می‌توان حذف واقعی را با `--apply` انجام داد. جزئیات هویت، استخراج و آزمون شبکه در `docs/ASSET-IDENTITY-AND-LIVE-TEST-FA.md` و `docs/DIAG-EXTRACT-COMMANDS-FA.md` است.
