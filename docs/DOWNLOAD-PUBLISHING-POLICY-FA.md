# قاعدهٔ ثابت انتشار بسته‌های دانلودی

این دستور برای همهٔ تحویل‌های بعدی سامانه الزامی است؛ برای هر بسته دوباره از کاربر نپرسید و صرفاً فایل ZIP را در مخزن رها نکنید.

1. **یک صفحهٔ دانلود جاری:** همان `downloads/index.html` تنها صفحهٔ عمومی دانلود باشد. لینک و عنوان صفحه را به آخرین ZIP یکتا به‌روزرسانی کنید؛ در صفحهٔ جاری، نسخه‌های قدیمی و فهرست/لینک تاریخچه نمایش داده نشوند.
2. **نام یکتا برای هر ZIP:** برای هر تحویل نام تازه و مشخص بسازید؛ ZIP قبلی را با نام قبلی بازنویسی یا دوباره عرضه نکنید. checksum کنار ZIP را بسازید و اعتبارسنجی کنید.
3. **انتشار واقعی، نه فقط تغییر محلی:** صفحه و ZIP باید در شاخهٔ فعال `arena/8edbdf95-ticket` ثبت و push شوند. پیش از اعلام تکمیل، لینک صفحه، لینک دانلود مستقیم، انتشار GitHub و checksum را از راه دور بررسی کنید.
4. **یک انتشار جاری:** برای هر تحویل یک GitHub Release یکتا بسازید و آن را `Latest` علامت بزنید؛ در متن انتشار، لینک مستقیم به ZIP دقیق همان تحویل و SHA-256 را بگذارید. اگر بارگذاری asset مستقیم ممکن نبود، لینک ZIP ثبت‌شده در شاخه را در صفحهٔ انتشار قرار دهید؛ خطای بارگذاری را پنهان نکنید.
5. **نسخه‌های قدیمی:** فایل‌ها و سوابق قدیمی را فقط برای آرشیو داخلی نگه دارید؛ آن‌ها را در صفحهٔ عمومی دانلود جاری فهرست نکنید. حذف دائمی آرشیو یا releaseهای تاریخی فقط با درخواست صریح جداگانه انجام شود.
6. **گزارش وضعیت:** به کاربر تنها وقتی بگویید بسته روی صفحه قرار گرفته که صفحه و لینک دانلود از راه دور واقعاً قابل مشاهده باشند. در غیر این صورت روشن و کوتاه بگویید کدام مرحله انجام نشده و علت چیست؛ کاربر را وادار به تکرار درخواست نکنید.
