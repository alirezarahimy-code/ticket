# گزارش بازیابی ماژول غذا — Ticket 1.61.10 R33

**مبنای بسته:** R31/R32 · **تاریخ:** ۲۰۲۶/۱۰/۲۴

## علت‌های پیدا‌شده

بررسی نسخه‌ها نشان داد بستهٔ R31 صفحه و `food-ticket.php` را جایگزین می‌کرد، اما تعدادی از وابستگی‌های PHP و assetهای پنل غذا را همراه نداشت. بستهٔ R32 دارایی‌های رابط را اضافه کرد، ولی هنوز دو فایل backend لازم را جا انداخته بود. این ناهم‌نسخه‌بودن با خطاهای گزارش‌شده تطبیق دارد:

- مسیر `food-menu/bulk-apply` در `food-order.php` تعریف می‌شود؛ نسخهٔ قدیمی آن پاسخ «مسیر API برنامه غذایی پیدا نشد» می‌دهد.
- تابع `food_ticket_manual_attendance_today()` در `food-ticket-groups.php` است و handler آن را فراخوانی می‌کند؛ نبودن نسخهٔ هماهنگ این فایل باعث خطای «undefined function» می‌شود.
- اگر فایل‌های فرانت‌اند جا بیفتند یا cache نسخهٔ قبلی را نگه دارد، ثبت دستی و عملیات گروهی هم در پنل ظاهر نمی‌شوند.

**این نقص بسته‌بندی از طرف من بود:** R32 را زودتر از آن‌که وابستگی‌های کامل backend را بررسی کنم، تحویل دادم. R33 همهٔ فایل‌های runtime غذایی را یکجا و هم‌نسخه می‌کند.

## محتویات اصلاحی

- فایل‌های PHP خود ماژول غذا و وابستگی‌های مستقیم `food-ticket.php`؛ ازجمله `food-order.php` و `food-ticket-groups.php`.
- صفحه و تمام assetهای JavaScript/CSS پنل غذا، شامل ثبت دستی، گروه‌ها و عملیات گروهی؛ نسخه‌های cache-busting در HTML حفظ شده‌اند.
- مهاجرت افزایشی `006-food-meal-type.sql`.
- فقط فایل‌های غذا و گزارش بسته؛ هیچ فایل تیکت عمومی، CD/DVD یا inventory داخل ZIP نیست.

## بررسی‌ها

- آزمون‌های Python غذا: **۸۰ موفق و ۱۸ زیربررسی موفق**.
- آزمون‌های JavaScript تقویم و نمایش منو: موفق؛ بررسی نحوی assetهای JavaScript غذا: موفق.
- نحو ۱۳ فایل PHP غذایی و ۷ آزمون PHP آفلاین: موفق؛ **۱۵۴ assertion بدون خطا** با PHP/WASM ۸.۵.۱۰ (نه PHP بومی نصب مشتری).
- آزمون کامل‌بودن ZIP کنترل می‌کند که handler، تابع ثبت دستی، مسیر API گروهی، assetها و مهاجرت همگی داخل بسته باشند.
- اجرای food-only روی دیتابیس دورریختنی در Actions پیش‌تر موفق بود؛ پس از این بسته روی دیتابیس نصب مشتری اجرای تازه‌ای انجام نشده است.

## نصب بازیابی

1. پیش از نصب از فایل‌ها و پایگاه‌داده نسخهٔ پشتیبان بگیرید.
2. همهٔ محتویات پوشهٔ `files/` را روی ریشهٔ برنامه کپی و فایل‌های هم‌نام را جایگزین کنید؛ فایل‌های PHP گروه و برنامهٔ غذا را جدا از یکدیگر به‌روزرسانی نکنید.
3. اگر مهاجرت وعده‌ها قبلاً اجرا نشده، `files/migrations/006-food-meal-type.sql` را یک‌بار روی دیتابیس اجرا کنید؛ پیش از اجرا نسخهٔ پشتیبان داشته باشید.
4. OPcache را پاک کنید یا سرویس PHP-FPM/Apache را restart کنید تا تابع‌های نسخهٔ قدیمی در حافظه نمانند.
5. مرورگر را با Ctrl+F5 تازه کنید و ثبت دستی، گروه‌ها و عملیات گروهی را بررسی کنید.
