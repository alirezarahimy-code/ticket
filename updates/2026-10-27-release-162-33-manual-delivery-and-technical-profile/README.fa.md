# نسخهٔ ۱.۶۲.۳۳ — فیش دستی/تحویل غذا و فرم شناسنامهٔ فنی

> این بسته با نسخهٔ ۱.۶۲.۳۴ جایگزین شده است. نسخهٔ جدید علاوه بر اصلاحات این بسته، ثبت‌های دستی قبلی را از فهرست غیبت نیز آشتی می‌دهد؛ برای نصب نسخهٔ ۱.۶۲.۳۴ را دریافت کنید.

**حداقل نسخهٔ پایه:** ۱.۶۲.۲۵  
**مهاجرت:** یک backfill افزایشی و idempotent برای فیش‌های دستیِ چاپ‌شدهٔ قبلی.

## فیش و تحویل

- رویداد تردد/`no_food` روز جاری برای کارمند دارای سفارش، هنگام صدور دستی درجا به رویداد فیش تبدیل می‌شود؛ رویداد تکراری ساخته نمی‌شود.
- فیش دستی بدون چاپ فیزیکی با `event_type=printed`، `print_status=printed` و `delivery_status=delivered` ثبت می‌شود.
- فیش دستی با چاپ فیزیکی پس از چاپ موفق توسط Worker تحویل‌شده می‌شود تا صف چاپ متوقف نشود.
- Migration یک‌بار، فیش‌های دستی قبلی را که `source_uid=manual-attendance` و وضعیت چاپ‌شده دارند تحویل‌شده می‌کند؛ فیش‌های در صف چاپ فیزیکی را تغییر نمی‌دهد.
- ثبت تردد بدون فیش تحویل غذا نیست. مسیر دستی همان فرم تنظیمات پنل غذا و فقط برای ادمین اصلی باقی می‌ماند.

## شناسنامهٔ سیستم

- بسته شامل `asset-profile.php`، `asset-inventory-page.php`، CSS هماهنگ و مسیر `index.php` لازم برای فرم ۷۴ فیلدی در ۹ بخش است.
- مسیر فرم: «شناسنامه‌های فنی» ← انتخاب سیستم ← «تکمیل دستی». صفحهٔ قدیمیِ جزئیات به فرم جدید هدایت می‌شود.
- خطای ساخت/افزودن ستون‌های پایگاه‌داده دیگر بلعیده نمی‌شود؛ پیام راهنما نشان می‌دهد دسترسی `CREATE/ALTER` روی `asset_profiles` و `assets` لازم است و جزئیات در گزارش سامانه ثبت می‌شود.

## نصب و پیگیری

1. این بسته از نسخهٔ ۱.۶۲.۲۵ تا ۱.۶۲.۳۲ قابل نصب است؛ روی نسخهٔ بالاتر downgrade نکنید.
2. پیش از نصب از فایل‌ها و پایگاه‌داده بکاپ بگیرید.
3. ZIP را از بخش به‌روزرسانی داخل سامانه بارگذاری کنید؛ دستی extract نکنید.
4. بعد از نصب، نسخه را در پنل بررسی کنید؛ سپس از «شناسنامه‌های فنی» یک سیستم را باز کنید، فیلد کم‌خطر را ذخیره و پس از refresh ماندگاری را بسنجید.
5. اگر پیام خطای schema دیدید، کاربر دیتابیس نیازمند مجوز `CREATE/ALTER` است. اگر پنل هنوز نسخهٔ پایین‌تری نشان می‌دهد، به‌روزرسانی نصب نشده است.

ZIP و manifest بررسی شدند. این بسته روی سرور واقعی نصب/تست نشده و استقرار را تضمین نمی‌کند.
