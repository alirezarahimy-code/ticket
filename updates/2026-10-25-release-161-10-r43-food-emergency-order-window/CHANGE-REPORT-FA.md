# گزارش R43 — مرتب‌سازی سفارش‌ها و مهلت اضطراری ثبت غذا

**تاریخ:** ۱۴۰۵/۰۸/۰۳ (۲۰۲۶/۱۰/۲۵)  
**نسخهٔ سامانه:** ۱.۶۱.۱۰  
**دامنه:** فهرست سفارش‌های غذای روزانه و ثبت سفارش کارکنان

## تغییرات

- با انتخاب ستون «نام و نام خانوادگی»، فهرست ابتدا بر اساس نام خانوادگی و سپس نام مرتب می‌شود؛ کلیک دوباره ترتیب معکوس را اعمال می‌کند. ترتیب اولیهٔ پاسخ مدیر نیز بر همین اساس است.
- مدیر دارای دسترسی `food.order_close` می‌تواند از تب «برنامهٔ روزانه»، برای یک تاریخ و یک وعدهٔ مشخص، مهلت استثنایی ثبت سفارش فعال کند. مدیرانی که فقط دسترسی بستن/بازکردن سفارش را دارند نیز می‌توانند این بخش را به‌صورت خواندنی ببینند و مهلت را مدیریت کنند.
- این مجوز دائمی نیست: فقط روز جاری یا حداکثر ۷ روز گذشته انتخاب می‌شود و مدت آن باید ۱، ۲، ۴، ۸ یا ۲۴ ساعت باشد. دلیل ۵ تا ۵۰۰ نویسه‌ای اجباری است؛ مدیر می‌تواند مهلت را زودتر لغو کند.
- مهلت به همان تاریخ و وعده محدود است و وضعیت عادی روز را بازنویسی نمی‌کند. سفارش فقط تا زمان انقضای مجوز پذیرفته می‌شود؛ ثبت و لغو مجوز در `food_order_logs` و audit سامانه نگه‌داری می‌شود. ثبت سفارش پس از پایان تاریخ یا بسته‌بودن روز، بدون مهلت فعال همچنان رد می‌شود.
- تغییر از جدول موجود `food_order_logs` استفاده می‌کند؛ migration یا تغییر پایگاه‌داده لازم نیست. فایل‌های پنل مستقل و میزبانی‌شده همگام شده‌اند و cache-busting بروزرسانی شده است.

## آزمون‌های موفق

- `python3 tests/test_food_emergency_order_window_static.py` — پنج بررسی دسترسی، محدودیت زمان/تاریخ، audit، UI و مرتب‌سازی موفق.
- `python3 tests/test_food_orders_static.py` — ۳۵ آزمون بخش سفارش غذا موفق.
- `node --check` برای `assets/food-menu.js`، `assets/food-order.js` و نسخهٔ میزبانی‌شدهٔ `food-menu.js` — موفق.
- `node tests/js/food-order-name-sort.test.js` — مرتب‌سازی صعودی/نزولی بر مبنای نام خانوادگی موفق.
- `node tests/js/food-menu-by-menu.test.js` و `node tests/test_food_order_calendar_node.js` — موفق.
- `git diff --check` برای فایل‌های تغییرکرده — موفق.

- PHP اجرایی و اتصال MySQL در این محیط موجود نیست؛ بنابراین API و ثبت سفارش روی پایگاه‌دادهٔ واقعی اجرا نشده‌اند. آزمون‌های PHP/DB عملیاتی انجام نشده‌اند.
- پیش‌نمایش مرورگری یا نصب روی production/staging اجرا نشده است. این تغییر فقط در branch محیط ایزوله اعمال شده است.
- آزمون‌های تیکت، CD/DVD و inventory خارج از محدودهٔ این اصلاح‌اند و اجرا نشده‌اند.
