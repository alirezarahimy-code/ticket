# گزارش تغییرات بستهٔ مستقل 1.62.2

## داشبورد غذا
- شمارندهٔ فیش چاپ‌شده دیگر یک رویداد موفق را دوبار به مجموع روزانه و نمودار اضافه نمی‌کند.
- فایل‌های محلی داشبورد R42 و stylesheet تم سراسری داخل ZIP قرار دارند تا نمایش داشبورد به باقی‌ماندن تصادفی assetهای قبلی وابسته نباشد.
- اگر bundle داشبورد بارگذاری نشود، پوستهٔ پنل خالی نمی‌ماند و کارت‌های خلاصه با پیام تشخیصی نمایش داده می‌شوند.
- در این محیط به دادهٔ واقعی نصب مشتری دسترسی نبود؛ بنابراین عدد ۱۸۰ در محیط مشتری قابل تأیید نبود و رفع کامل در production ادعا نمی‌شود.

## تم روز/شب
- دکمهٔ تم از action صحیح پنل استفاده می‌کند و `data-theme-mode` را روی ریشهٔ سند و body تغییر می‌دهد؛ حالت سراسری روی سربرگ، منو و کل پوسته اعمال می‌شود، نه فقط داشبورد مرکزی.
- نسخهٔ cache-busting فایل‌ها و نسخهٔ پنل افزایش یافت.

## عملیات گروهی برای روز گذشته
- سفارش گروهی و لغو گروهی فقط در صورت داشتن مجوز عملیات اضطراری و فعال‌بودن مهلت مدیر برای همان تاریخ و وعده مجاز است.
- این شرط هم در UI، هم در API گروهی و هم در بررسی تراکنشی روز/سفارش اعمال می‌شود؛ با پایان مهلت، عملیات دوباره مسدود است.
- تغییر سلف برای تاریخ گذشته همچنان غیرفعال است. لغو گروهی همچنان دلیل اجباری و ثبت audit دارد. دسترسی دائمی یا سراسری ایجاد نشده است.

## بسته و آزمون
- بستهٔ مستقل و آفلاین، بدون migration و وابستگی ابری است؛ بسته‌های قبلی از جمله R34 تا R43 و 1.62.1 دست‌نخورده باقی مانده‌اند.
- آزمون‌های static مرتبط اجرا شدند: ۳۹ آزمون food panel/order، شش آزمون bulk operations، پنج آزمون مهلت اضطراری، و بررسی هم‌خوانی تم پنل. دو آزمون رفتاری Node برای شمارش چاپ‌شده و مجازبودن انتخاب گروهی روز گذشته نیز موفق شدند؛ بررسی نحوی JavaScriptهای تغییرکرده و سه اسکریپت inline پنل هم موفق بود.
- PHP CLI و مرورگر در این محیط موجود نبودند؛ parse نحوی PHP و آزمون مرورگری/پایگاه‌داده انجام نشد. production/staging بررسی نشده است.
- آزمون‌های تیکت، CD/DVD و inventory عمداً اجرا نشدند.
