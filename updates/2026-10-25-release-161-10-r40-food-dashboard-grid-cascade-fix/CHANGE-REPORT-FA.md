# گزارش اصلاح اندازه‌بندی داشبورد غذا — R40

**تاریخ:** ۱۴۰۵/۰۸/۰۳ (۲۰۲۶/۱۰/۲۵)  
**نسخهٔ سامانه:** ۱.۶۱.۱۰  
**مبنای اصلاح:** مقایسهٔ مختصات تصویر کاربر با CSS و باندل R39

## علت دقیق ایراد

صفحهٔ میزبان یک قانون عمومی و خارج از لایه‌های CSS با نام `.grid` دارد که چهار ستون، فاصله و margin سراسری تعیین می‌کند. CSS داشبورد R39 کلاس‌های Tailwind را داخل `@layer` نگه می‌دارد؛ در نتیجه قانون بدون‌لایهٔ میزبان از کلاس‌هایی مثل `xl:grid-cols-3` و `gap-3` قوی‌تر می‌شد. نتیجه در مختصات صفحه: ردیف جزئیات عملاً چهار ستون می‌گرفت؛ نمودار دو ستون و «وضعیت امروز» یک ستون را می‌گرفتند و یک ستون خالی می‌ماند. همان قانون، margin و فاصلهٔ اضافی را به تمام gridهای داخلی هم تحمیل می‌کرد.

## اصلاح انجام‌شده

- در CSS محدود به `.food-capitalio-dashboard-widget .grid`، چهار ویژگی `display`, `grid-template-columns`, `gap` و `margin` با `revert-layer` به utilityهای خود داشبورد برگردانده شدند؛ CSS دیگر ماژول‌ها تغییر نمی‌کند.
- در عرض دسکتاپ ۱۷۱۱ پیکسل، چهار کارت شاخص در یک ردیف می‌مانند و ردیف جزئیات به نسبت ۲:۱ (نمودار دو سوم، وضعیت امروز یک سوم) تبدیل می‌شود؛ ستون خالی حذف می‌شود.
- فایل JS، داده‌ها، رنگ‌ها، API و رفتار محاسباتی تغییر نکرده‌اند. داده‌های نمونه همچنان فقط در پیش‌نمایش هستند.

## آزمون متمرکز

- Chromium پیش از اصلاح: grid جزئیات چهار track داشت؛ chart برابر ۷۸۷px، وضعیت ۳۸۶px و یک track خالی.
- Chromium پس از اصلاح در viewport ۱۷۱۱px: grid سه track شد؛ نمودار ۱۰۵۵px، وضعیت ۵۲۲px، بدون track خالی.
- در viewport ۱۱۶۲px، breakpoint دو ستونهٔ KPI فعال است و ردیف جزئیات طبق breakpoint به یک ستون می‌رود.
- پاسخ‌های صفحه و ZIP و بررسی سلامت archive جداگانه ثبت می‌شوند.

## محدودیت

این اصلاح در preview محلی/ایزوله و باندل قابل‌دانلود بررسی شده است؛ نصب روی سرور مشتری یا backend واقعی انجام نشده. آزمون‌های تیکت، CD/DVD و inventory اجرا نشدند.
