# گزارش تغییرات R38 — رفع صفحهٔ خالی داشبورد غذا

**تاریخ:** ۱۴۰۵/۰۸/۰۳ (۲۰۲۶/۱۰/۲۵)  
**نسخهٔ سامانه:** ۱.۶۱.۱۰  
**مبنای اصلاح:** بستهٔ R37 داشبورد غذا

## علت ریشه‌ای

باندل `food-capitalio-dashboard-r37.js` چندین ارجاع خام به `process.env.NODE_ENV` داشت. در مرورگر عادی، `process` تعریف نشده بود و Chromium خطای `ReferenceError: process is not defined` ثبت می‌کرد؛ در نتیجه mount داشبورد متوقف می‌شد و صفحه خالی می‌ماند. افزودن shim موقت به صفحهٔ پیش‌نمایش این ایراد بستهٔ R37 را پنهان می‌کرد، اما آن را در خود باندل حل نمی‌کرد.

## اصلاح R38

- shim محدود و محلیِ `process.env.NODE_ENV="production"` به ابتدای باندل R38 افزوده شد تا همهٔ کدهای داخلی باندل آن را ببینند؛ به `window.process` یا وابستگی آنلاین نیاز نیست.
- `food-ticket-web/index.html` به نام‌های نسخه‌دار R38 برای JavaScript و CSS اشاره می‌کند تا مرورگر فایل‌های R37 را از cache استفاده نکند.
- هیچ دادهٔ نمونه‌ای به محصول اضافه نشده و هیچ migration یا تغییر backend در این بسته نیست.

## فایل‌های بسته

- `food-ticket-web/index.html`
- `food-ticket-web/assets/food-capitalio-dashboard-r38.js`
- `food-ticket-web/assets/food-capitalio-dashboard-r38.css`
- فونت‌های محلی نسخه‌دار R37 که همچنان توسط CSS داشبورد استفاده می‌شوند
- manifest و این گزارش

## آزمون‌های انجام‌شده

- `node --check` روی باندل R38: موفق.
- Chromium headless روی preview: ریشهٔ داشبورد mount شد، عنوان‌ها و کارت‌های داشبورد در DOM حاضر بودند و خطای uncaught JavaScript ثبت نشد.
- درخواست مستقیم archive از preview: `200 OK`, `application/zip`; hash فایل سرو‌شده با archive محلی برابر بود.
- `unzip -t` و SHA-256 بسته: موفق.

## دادهٔ پیش‌نمایش

پیش‌نمایش ایستا backend محلی سامانه را ندارد. برای بررسی دیداری، فقط در کپی موقتِ preview (نه در فایل محصول و نه در ZIP) دادهٔ نمونهٔ صریحاً برچسب‌خورده تزریق شده است. بستهٔ R38 هیچ fixture یا دادهٔ ساختگی ندارد؛ محصول در نبود API همچنان حالت خالی صریح خودش را نشان می‌دهد.

## آزمون‌های انجام‌نشده

- آزمون‌های تیکت، CD/DVD و inventory اجرا نشدند؛ خارج از محدودهٔ این اصلاح‌اند.
- نصب روی سرور مشتری و اتصال به دیتابیس/منابع واقعی در این محیط انجام نشد.
