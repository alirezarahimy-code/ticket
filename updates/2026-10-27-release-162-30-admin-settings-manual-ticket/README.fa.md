# نسخهٔ ۱.۶۲.۳۰ — ثبت دستی فیش فقط در تنظیمات و فقط برای ادمین اصلی

> **اصلاح امنیتی:** بستهٔ ۱.۶۲.۲۹ به دلیل نمایش امکان ثبت دستی فیش در سفارش اضطراری برای دارندگان دسترسی `food.emergency` لغو شده است. آن بسته را نصب نکنید. اگر نصب شده، این نسخه را سریعاً جایگزین کنید.

**حداقل نسخهٔ پایه:** ۱.۶۲.۲۵ (تا ۱.۶۲.۲۹ قابل نصب است)

**مهاجرت دیتابیس:** ندارد

## تغییرات و محدودیت دسترسی

- دکمهٔ ثبت دستی از پنل سفارش اضطراری حذف شده است؛ مسیر API آن نیز دیگر مجاز نیست.
- بخش **«ثبت دستی فیش»** فقط در «تنظیمات سامانه» و فقط برای `primary_admin` نمایش داده می‌شود.
- کد دسترسی `food.manual_ticket` به فهرست «نقش‌ها و دسترسی‌ها» اضافه شده است؛ کد فقط برای `primary_admin` مؤثر است و برای نقش‌های دیگر، حتی تنظیمات سفارشی، رد می‌شود.
- ثبت نیازمند سفارش فعال همان کارمند/تاریخ، تطبیق کد ملی و علت ۵ تا ۵۰۰ نویسه‌ای است.
- رویداد فیش با `event_type=printed` و `print_status=printed` درج/تکمیل می‌شود؛ چاپگر فراخوانی نمی‌شود. شناسهٔ ادمین، سفارش، علت و علامت `issued_without_physical_print` در payload و Audit ثبت می‌شوند.
- وضعیت تحویل غذا دست‌نخورده می‌ماند؛ این ثبت به‌تنهایی تحویل غذا را تأیید نمی‌کند.

## نصب و آزمون

1. پیش از نصب از پایگاه‌داده و فایل‌ها بکاپ مستقل بگیرید.
2. نصب روی ۱.۶۲.۲۵ تا ۱.۶۲.۲۹؛ روی نسخهٔ بالاتر از ۱.۶۲.۳۰ downgrade نکنید.
3. ZIP را از به‌روزرسانی داخل سامانه بارگذاری کنید؛ دستی extract نکنید.
4. با حساب مدیر پشتیبانی بررسی کنید دکمهٔ ثبت دستی در سفارش اضطراری دیگر وجود ندارد.
5. با ادمین اصلی به «تنظیمات ← ثبت دستی فیش» بروید، یک سفارش تأییدشده و علت مستند را انتخاب کنید، سپس وضعیت رویداد و گزارش غایبین را بازبینی کنید.
6. در «نقش‌ها و دسترسی‌ها» بررسی کنید مجوز `ثبت دستی فیش بدون چاپ فیزیکی` برای نقش‌های غیرادمین قابل اعطا نیست.

برای rollback فایل‌های بسته را از بکاپ قبلی برگردانید. با توجه به لغو ۱.۶۲.۲۹، در صورت نصب آن، برای حفظ محدودیت دسترسی این نسخه را جایگزین کنید نه اینکه به ۱.۶۲.۲۹ بازگردید.

ZIP، manifest، مسیرها، نحو JavaScript و آزمون‌های ایستای مرتبط بررسی می‌شوند؛ نصب روی سرور واقعی انجام نشده است و PHP lint در محیط توسعه موجود نیست.
